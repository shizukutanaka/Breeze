# COMPETITIVE-ADVANTAGE — 競合優位性の反復記録

目的: 「イーロン・マスク思考法＋ソクラテス問答法で、競合優位性が立つまで思考を続ける」（2026-11-20、mi の指示）への回答。優位性の候補を立てては問答で殺し、生き残ったものだけを優位性と呼ぶ。殺した候補と理由も成果物の一部として残す。

土台は repo の現行文書の実測（README、[COMPARISON.md](COMPARISON.md)、[COST_MODEL.md](COST_MODEL.md)、[SUSTAINABILITY.md](SUSTAINABILITY.md)、[SHARE_PLAN.md](SHARE_PLAN.md)、[FIRST-PRINCIPLES.md](FIRST-PRINCIPLES.md)、[ANTENNA_PLAN.md](ANTENNA_PLAN.md)）と、出典つきの外部調査（末尾の出典一覧）。過去の検討（FIRST-PRINCIPLES 問4「堀は LINE が構造的に実装できないもの」、SHARE_PLAN 第3節の勝ち筋）は土台にしたが、鵜呑みにせず全て問答にかけ直した。

結論を先に書く: **優位性は条件付きで立った。** ただしそれは機能の優位ではなく、費用と所有の構造の優位であり、「成長のエンジン」ではなく「死なないことと、波の日に受け皿として完成していること」の優位である。第4節に正確な文で書く。第5節に、それを本物にするための製品変更と、優位が無効になる条件を書く。

## 1. 競合の再定義 — 相手は本当に LINE と Signal か

### 1.1 問い: 乗り換えは誰の単位で起きるか

メッセンジャーの乗り換えは個人の単位では起きない。相手がいないメッセンジャーに価値はなく、実際に動くのは **小グループ（家族・友人・コミュニティ）の単位** である。SHARE_PLAN 第3節が集団 A〜E を切ったのも同じ観測であり、本書もこれを採用する。したがって競合とは「個人の端末のデフォルトの座」ではなく「小グループが移る先の候補集合」である。

### 1.2 市場の二層構造

候補集合は二層に分かれる。

| 層 | 住人 | 性質 |
|---|---|---|
| 日常の本命 | LINE（日本）、WhatsApp（世界）、Telegram、iMessage、Discord | ネットワーク効果で固定。正面から奪う手段は存在しない |
| 逃げ先（受け皿） | Signal、SimpleX、Session、Briar、Matrix/Element、Breeze | 本命の事件・改悪・遮断のたびに「波」が来て、その波の中だけでシェアが動く |

実証: 2021年1月の WhatsApp 規約変更では、Signal が5日間で約750万インストール [W1]、Telegram が72時間で2,500万人増 [W2] を得た。平常時に機能比較で動いた数字ではない。**シェアは波の中でだけ動き、波は自分では作れない。** 作れるのは「波の日に、完成品として、見つけられる場所に居ること」だけである。

### 1.3 競合集合の確定

| 競合 | 規模（出典つき） | Breeze との関係 |
|---|---|---|
| LINE | 日本の月間利用者 約1億アカウント [内部 L1]。LY の売上 2兆363億円（FY2025）のうちメディア事業 7,351億円 | 日本の本命。日常の厚みでは比較にならない |
| WhatsApp | 月間 30億人超（2025年 Q1 決算）[W3] | 世界の本命 |
| Telegram | 月間 10億人（2025年3月）[W4]。既定では E2EE でなく（秘密チャットのみ、グループ E2EE なし）、電話番号必須 | 本命と受け皿の中間。波の最大の受益者 |
| Signal | 月間 7,000万〜1億人（2025年4月、Whittaker 発言）[W5] | 受け皿の現王者。プライバシーの心象を所有している |
| SimpleX | 月間 約60万人（運営会社自己申告）[W6]、コミュニティ運営サーバー 1,000超 [W6] | 同土俵で最も構造が近い。ユーザー ID 自体を持たない |
| Session | 月間 100万人超・ノード 2,200超（プロジェクト申告、2025年2月）[W7] | トークンステーク経済の上に立つ受け皿 |
| Briar | 規模非公開。2026年7月に保守モード入り [W8] | 最も純粋な P2P。しかし日常の移行先にはならない |
| Matrix / Element | 聯邦の既知アカウント 1.9億、公開聯邦の月間利用者 115万人（財団年次報告 2025）[W9] | 聯邦・自己ホストの先行者。身元はホームサーバに束縛 |

**再定義の結論**: 目標の文「LINE と Signal のシェアを取りに行く」は、二層の意味に分解しないと空転する。LINE からは「波の日に小グループごと」しか取れず、Signal とは「受け皿の座」を争う。Breeze の競合優位性は、この二つの争いの両方に効く形でなければならない。

## 2. お金の流れの分解 — 費用構造が戦略の自由度を縛る

| 運営 | 誰が払うか | 実数 | 構造が禁止すること |
|---|---|---|---|
| LY（LINE） | 広告主・事業者・決済利用者 | FY2025 売上 2兆363億円。メディア事業 7,351億円（広告: ディスプレイ 2,542億・検索 1,790億・アカウント 1,457億円）、戦略事業（PayPay 等）4,457億円 [W10] | メッセージングは広告と公式アカウント課金の入口である。広告ゼロ・エンゲージメント最大化の放棄・全面 E2EE 化（公式アカウントやサーバー側 URL プレビューと衝突）は、収益の柱そのものを壊すので選べない |
| Meta（WhatsApp） | Meta の広告事業全体 | 有料ビジネスメッセージングが年換算 $20億のランレート（2025年 Q4）[W3]。本体は Meta の広告収益（2025年売上 $2,010億 [W3]）が補助 | 無料でいられるのは監視型広告の本体が払うから。Updates タブへの広告導入が進む方向にあり、「広告なし」は Meta の約束ではない |
| Telegram | Premium 利用者・広告・債券・トークン連動収益 | 2024年 売上 $14億・利益 $5.47億（Durov 発表／FT 報道）[W4]。Premium 1,500万人（2025年5月）[W4]。約4年で $20億の債券発行 [W4] | 中央サーバーの費用を払い続けるために収益化の拡大が必須。既定 E2EE 化はプラットフォーム機能（チャンネル・ボット・検索）の基盤と衝突する |
| Signal 財団 | 寄付者（毎年、調達し直す） | FY2024（Form 990）: 収入 $2,941万に対し支出 $3,802万、**赤字 $861万** [W5]。運営必要額は 2025年に年 約$5,000万の見通し（公式ブログ 2023年: インフラ 約$1,400万のうち登録 SMS が約$600万、職員 約50名で約$1,900万）[W11] | 基盤は財団の所有であり、寄付調達が止まれば基盤が止まる。利用者が基盤を持ち帰る設計（聯邦・自己ホストで相互接続）は公式に存在しない — それは財団の存立条件（唯一の基盤であること）と衝突する |
| SimpleX Chat Ltd | 投資家＋寄付＋クラウドファンディング | 2024年に $130万のプレシード（Jack Dorsey ら）[W12]、2025年に Buterin から約$38万の寄付 [W12]、2026年に株式型クラウドファンディング [W6]。サーバー運営者向けのトークン（Community Vouchers）による収益化を計画 [W6] | 株式会社であり、投資家への説明責任がある。「誰も払わない」構造には進めず、運営の収益化（バウチャー等）を発明し続けなければならない |
| Session 財団 | トークン（SESH）のステーク経済 | ノード運営には 25,000 SESH のステークが必要 [W7]。運営は 2024年にスイスの財団へ移管 [W7] | ネットワークの存続がトークン価格とステーク参加率に結ばれている。価格の暴落はそのまま基盤の縮小になる |
| Matrix.org 財団 | 会員費・寄付・有料アカウント | 2025年2月の公式ブログ「Crossroads」: 財団は収入の約2倍を支出し、matrix.org の有料アカウント導入とブリッジ停止に踏み切った [W13] | 聯邦でも「既定サーバーと仕様策定」という中心には費用が集中し、その中心は毎年の資金調達から逃げられない。身元（@user:server）はホームサーバに束縛され、アカウント可搬性は 2026年時点で「開発中」[W14] |
| Briar | 助成金＋ボランティア | 2025年に資金不足でプロジェクト終了を決め、2026年7月に保守モード（セキュリティ修正のみ）へ移行 [W8] | サーバー費用ゼロでも「開発の継続」には金が要る。純粋な P2P はここで止まった |

**分解の結論**: 全ての競合に共通するのは「中心に、毎年払い続けなければならない誰かがいる」ことであり、その支払者が各社の戦略の自由度を決めている。広告主が払う者は「読めない化」に進めず、寄付者が払う者は「唯一の基盤」であることを手放せず、投資家・トークンが払う者は収益化の発明を止められない。Breeze の費用方針（[COST_MODEL.md](COST_MODEL.md) 第10節: 既定リレーは入口の無償枠のみ、超過は利用者自身の置き場所が負担、作成者は払わない）は、この表の中で唯一「払う者がいない」行である。この非対称が第3節の問答の出発点になる。

## 3. 候補と問答の反復履歴 — 立てては殺す

判定は3種: **殺す**（優位ではない）、**格下げ**（事実だが差別化ではない。衛生水準または入口の部品として残す）、**残す**（優位の構成要素になる）。

### 候補1: 量子耐性（PQXDH が既定 ON）→ **殺す**

- 問: Signal も PQXDH を持つのではなかったか。
- 反証: Signal は PQXDH（2023年）に加えて SPQR／Triple Ratchet（2025年）で継続的な PQ リキーイングまで進んでおり、Breeze より深い [内部 S3]。Apple の iMessage は PQ3（2024年、初期確立＋継続リキーイングの「Level 3」）を全利用者に配備済み [W15]。Session も Protocol V2（2025年12月）で ML-KEM を追加した [W7]。Breeze の PQXDH は「開始時のみ」で、この軸では中位に過ぎない（[COMPARISON.md](COMPARISON.md) も正直にそう書いている）。
- 決定的な反証: 利用者がメッセンジャーを量子耐性で選んだ証拠はどこにもない。Signal の成長は事件の波と心象で説明され、PQXDH の発表（2023年）が利用者数を動かした記録はない。
- 判定: 優位ではない。衛生水準として維持するが、売りにしない。

### 候補2: P2P アーキテクチャ → **殺す**（単独では）

- 問: P2P の先行者はいないのか。
- 反証: Briar は Tor／Bluetooth／Wi-Fi の完全 P2P で先行し [W8]、Session はオニオンルーティング [W7]、SimpleX は中継キューの設計で先行する [W6]。そもそも Breeze は純 P2P ではなく、オフライン配送のために封緘メールボックス（リレー）を持つハイブリッドである。
- 逆向きの反証: WebRTC の直接接続は、連絡先に対して自分の IP アドレスを見せる。SimpleX はあえて全てを中継に通し IP を連絡先からも隠す設計であり、メタデータの軸では Breeze の方が弱い面がある。P2P を無条件の美点として主張すると、この一点で反証される。
- 判定: 優位ではない。ただし P2P 直送は「預けを発生させない＝中心の費用を消す」仕組みとしては第4節の優位の部品になる。売りは配送方式ではなく費用の帰結の方である。

### 候補3: 電話番号が不要 → **格下げ**

- 問: 番号不要は Breeze だけか。
- 反証: SimpleX はユーザー ID 自体を持たず（番号どころか固定 ID が存在しない）[W6]、Session・Briar も番号不要 [W7][W8]。固有性はない。
- 残る事実: LINE・WhatsApp・Telegram・Signal の全てが登録に電話番号を要求する [内部 S1]。つまり「大手との差」としては入口で効くが、「逃げ先の中での差」にはならない。なお到達可能性では非対称がある: SimpleX の発見はリンク／QR の交換のみで安定した住所を持たないのに対し、Breeze は `@alias@relay` という到達可能な住所を持つ [COMPARISON.md]。ただしこれは機能差であり堀ではない。
- 判定: 入口の部品として残す。優位とは呼ばない。

### 候補4: 広告なし・追跡なし・プライバシー → **格下げ**

- 問: FIRST-PRINCIPLES 問4 の試金石「LINE が出荷できるか」で差別化になるとした判断は生きるか。
- 反証: その試金石は LINE に対しては今も正しい（第2節: 広告は LY の収益の柱であり、構造的に選べない）。しかし受け皿の座を争う Signal・SimpleX・Session も広告なし・追跡なしであり、この軸では並ぶだけである。さらに「プライバシー」という心象の所有者は Signal であり、Breeze が同じ言葉を掲げても想起では負ける。
- 判定: LINE に対する構造差としては事実だが、優位の主文にはならない。主文は「なぜ広告を入れられないのか」の構造（第4節）に置く。

### 候補5: 無料 → **殺す**

- 反証: 全競合が利用者には無料である。違うのは「誰が払うか」だけであり、それは候補ではなく第2節の分解そのもの。無料は主張にならない。

### 候補6: オープンソース（MIT） → **殺す**（単独では）

- 反証: Signal・SimpleX は AGPL、Briar は GPL、Matrix もオープンソースである [W6][W8][W9]。MIT の許容性（フォークして商用にも使える）は開発者向けの性質で、利用者の選択理由にはならない。
- ただし「誰でも同一物を再配備できる」という性質は、ライセンス単体ではなく単一ファイルのクライアントと交換可能なリレーと組み合わさったときに意味を持つ。それは候補10の部品として扱う。

### 候補7: 自己ホストできる → **変形して残す**

- 問: 自己ホストは Matrix と SimpleX にもあるのでは。
- 反証（原型への）: その通りであり、「自己ホスト可能」の一文は差別化にならない。Matrix の聯邦は 1.9億の既知アカウントを持つ規模の実績もある [W9]。
- しかし形を実測すると非対称が残る:
  - Matrix: 身元は `@user:server` としてホームサーバに束縛され、アカウントの可搬性は 2026年時点で開発中 [W14]。自己ホストの実務はホームサーバ＋認証基盤＋通話基盤＋DB の複数構成で重い [W16]。既定サーバー（matrix.org）の運営費は財団の赤字の中心にある [W13]。
  - SimpleX: サーバーはアカウントを持たないが、既定ネットワークは運営会社のサーバーが担い、発見はリンク交換のみで、身元の「住所」がない [W6]。
  - Breeze: 身元は鍵そのものでどのリレーにも属さない。リレーはアカウントを持たない封緘私書箱であり、連絡先ごとにホームリレーが違ってよく、複数リレーへ同時に預けられる（[COMPARISON.md](COMPARISON.md)、テストで固定）。クライアントは単一ファイル、リレーは約60秒で同一物を再配備できる [SUSTAINABILITY.md 第4節]。
- 判定: 「自己ホスト」の語は殺す。残るのは **「身元が置き場所に属さないこと」と「私書箱の交換可能性」** という特定の形であり、候補10の部品になる。

### 候補8: 履歴インポート（LINE／WhatsApp／Telegram） → **格下げ**（入口の楔）

- 反証: 実装すれば誰でも真似できる。堀ではない。Signal でさえ WhatsApp の履歴を取り込めない現状 [W17] では「波の日に、過去を持って移れる」唯一の受け皿である点は効くが、それは優位ではなく受け皿の完成条件である。
- 判定: 第5節の入口設計の部品。優位とは呼ばない。

### 候補9: アンテナ（利用者の端末が基盤になる） → **現時点では主張できない**

- 反証: [ANTENNA_PLAN.md](ANTENNA_PLAN.md) は設計のみで、実装は別判断と明記されている。未実装のものを優位と呼ぶのは、この repo の「看板と実態の一致」の規則に反する。
- 判定: 殺すのではなく保留。実装されれば候補10を強める（中心の縮小をさらに進める）ため、第5節の「作る」に条件付きで置く。

### 候補10: 運営者がいない構造 — 中心の費用がゼロに漸近し、誰もネットワークを所有できない → **残す（中核）**

主張の形: Breeze は、身元＝鍵（リレー非束縛）、リレー＝アカウントを持たない交換可能な封緘私書箱、費用＝利用者自身の置き場所への分散、という3点の合成により、「運営主体の資金が尽きてもネットワークが止まらず、利用が伸びても中心の請求が伸びず、作成者を含む誰も利用者のデータを所有できない」構造を持つ。

問答:

- 問: Briar も運営者がいないのではないか。
  - 答: その通りであり、Briar はこの主張の最も強い反例候補である。しかし実測すると、Briar は 2025年に資金不足で終了を決断し保守モードに入った [W8]。ここから読み取るべきは二つある。(a) サーバー費用ゼロでも「プロジェクトの継続」には金が要り、止まるのは開発の方である。(b) それでも Briar のネットワーク自体は止まっていない — 保守モードでも使い続けられている [W8]。つまり「止められない」は Briar と共有する性質であり、Breeze の固有性はそこだけには置けない。固有性は合成の方にある: Briar は iOS がなく、ファイル添付がなく、グループは小さく、「LINE の小グループが日常のまま移る」完成度を持たない。**「止まらない」ことと「移れる完成度」の両方を持つのは Breeze だけ**、という形でのみ主張が立つ。
- 問: Signal が寄付で年 $5,000万を集め続けられるなら、構造の差は実害にならないのではないか。
  - 答: 集め続けられる保証はどこにもなく、直近の実績は収入 $2,941万・支出 $3,802万の赤字である [W5]。より本質的には、Signal の基盤は財団の所有物であり、仮に資金が続いても「利用者が基盤を持ち帰って相互接続する」未来は Signal の設計に存在しない。Breeze の主張は Signal の破綻予測ではなく、「所有の所在」の差である: Breeze には、止める権利を持つ者が構造的に存在しない。
- 問: 中心の費用は本当にゼロか。COST_MODEL の数字は違うのではないか。
  - 答: 正確には「中心の費用は、既定をホームとする利用者数にのみ比例し、ネットワーク全体の利用者数からは切り離されている」である。1つのリレーが 100万 MAU を全部背負えば月 $43,216〜$279,317 かかるのが実測であり [SUSTAINABILITY.md 第1節]、それを否定しない。優位は「1か所が背負う必要がない」ことと、最悪値がフェアユース上限で身元ごとに固定されること（[COST_MODEL.md](COST_MODEL.md) 第10節）、限界費用が 1 MAU あたり月 $0.043（軽い利用、削減レバー適用後は $0.016）まで下がること [COST_MODEL.md 第4.3節] にある。コミュニティが自分の置き場所（定額 VPS 級）へ持ち帰るほど、既定リレーの請求はシェアの伸びから切り離される [COST_MODEL.md 第9節]。
- 問: それは利用者が増えなければ意味のない優位ではないか。
  - 答: その通りであり、これが本書の最も重要な留保である。この優位は **成長のエンジンではなく、存続と受け皿の優位** である。第1節の通りシェアは波の中でしか動かない。波は作れないが、波の日に「生きていて、完成していて、見つけられる」ことは作れる。Signal は波を待つ間に年 約$5,000万を燃やし [W11]、Briar は待つ間に開発が止まり [W8]、Matrix 財団は待つ間に既定サーバーの有料化に追い込まれた [W13]。Breeze の中心は無料枠〜月 $5 の水準で無期限に待てる。**時間の価格が全競合と違う** — これが候補10の実用上の帰結であり、第4節ではこれを優位の一部として明記する。
- 問: 作成者（mi）個人が開発を止めたら同じではないか。
  - 答: 開発の継続については同じリスクを認める（候補10は開発速度の主張をしない）。違うのは、開発が止まっても既存のネットワークと再配備可能性が残ること、そして MIT＋単一ファイルという形が「他人が引き継ぐ費用」を最小にすることである。Briar の保守モードが示す通り、引き継ぎも再開も、ソフトウェアが残っていれば起こりうる。

### 候補11: 外部監査・実績 → **優位ではなく負債として記録**

Signal のプロトコルは公開の分析を受け、実績がある。Breeze の暗号は仕様とテストで裏付けられるが独立した外部監査を受けていない [COMPARISON.md]。これは問答の対象ではなく、優位の文に混ぜてはならない事実としてここに固定する。第4節の優位は暗号の強さの主張を含まない。

### 反復の集計

候補11件のうち、殺したもの4件（量子耐性、P2P、無料、オープンソース単独）、格下げ3件（電話番号不要、広告なし、履歴インポート）、主張不能1件（アンテナ）、変形して残したもの1件（自己ホスト→身元の非束縛と私書箱の交換可能性）、負債として記録1件（監査・実績）、中核として残したもの1件（運営者の不在と費用の非集中）。**優位と呼べるのは候補10を中核とし、候補7の変形を部品とする合成だけである。**

## 4. 生き残った競合優位性（正確な文）

> **Breeze の競合優位性は、機能ではなく、費用と所有の構造にある。**
> 身元は鍵そのものでどのリレーにも属さず、リレーはアカウントを持たない交換可能な封緘私書箱であり、中心（既定リレー）の費用は「既定をホームとする利用者数」にだけ比例して、コミュニティが自分の置き場所へ持ち帰るほど縮む。したがって Breeze は、
> (1) 運営主体の資金が尽きてもネットワークが止まらず、
> (2) 利用が伸びても中心の請求が伸びず、
> (3) 作成者を含む誰も利用者のデータを所有できない、
> という3点を同時に満たしながら、「小グループが日常のまま移れる完成度」（全グループ 1,000 人までの E2EE、通話、LINE／WhatsApp／Telegram からの履歴インポート、登録なし・インストールなしの入口）を持つ、唯一のメッセンジャーである。

誰に対して、何が、なぜ真似できないか:

| 相手 | 何が差か | なぜ真似できないか |
|---|---|---|
| LINE / WhatsApp / Telegram（本命） | 運営が読めない全面 E2EE、広告・追跡の不在、電話番号なし、中心を持たない費用構造 | 彼らの支払者（広告主・事業者・Premium と債券）が、メッセージングを入口とする収益構造を要求する。「読めない化」と「誰も払わない化」は収益の柱と衝突する（第2節） |
| Signal（受け皿の王者） | 基盤の非所有と費用の非集中。利用者が自分の置き場所を持ち帰って相互接続できること | Signal の基盤は財団の所有であり、寄付モデルは「唯一の基盤」を前提に成り立つ。聯邦化は財団の存立条件と衝突する。加えて Signal には登録 SMS（年 約$600万 [W11]）という、Breeze が構造的に持たない費用が残る |
| SimpleX / Session（同土俵） | 日常の完成度（グループ通話、1,000 人グループ、履歴インポート、ブラウザだけの入口、日本語を含む8言語）と、存立が投資家・トークン価格に結ばれていないこと | SimpleX は株式会社であり投資家への説明責任と収益化（バウチャー）の発明義務を負う [W6][W12]。Session はノード経済がトークンのステークに依存する [W7]。どちらも「誰も払わない」行には移れない |
| Briar / Matrix（構造の先行者） | 「止まらない」ことと「移れる完成度」の両立（Briar に対して）。身元が置き場所に属さないことと、60秒で同一物を再配備できる軽さ（Matrix に対して） | Briar は日常の完成度を持たないまま保守モードに入った [W8]。Matrix は身元のホームサーバ束縛と、中心（財団・既定サーバー）の赤字を構造に抱える [W13][W14] |

優位の性質についての留保（隠さない）:

- これは **存続と受け皿の優位であり、成長のエンジンではない**。ネットワーク効果が支配的な市場で、構造の正しさ自体は利用者を連れてこない。効くのは「波の日に、生きていて、完成していて、見つけられる」形になったときだけである。
- 暗号の強さ・実績・規模では Signal に負けている（候補11）。優位の文はその主張を含まない。
- 優位の成立には第5節の前提条件（既定インスタンスの稼働、受け皿導線の実機確認）が要る。**現時点で既定インスタンス（breeze.pages.dev）は 404 であり、この優位は「潜在」していても「発動」していない。** 文書の上の優位と実態の一致は、前提条件が満たされて初めて成立する。

## 5. 優位を本物にするために — 製品変更と入口の設計

### 5.1 前提条件（これが無いと優位は存在しない）

1. **既定インスタンスの復旧**（所有者の Cloudflare 操作）: 配布済みアプリの既定接続先であり、404 の間は受け皿が閉じている。SHARE_PLAN 第0節の登録済み手順で復旧し、あわせて本番構成フラグ（DO バックエンド＋WS）を固定する（[COST_MODEL.md](COST_MODEL.md) 第5.2節: フラグの有無で無料枠の耐量が桁で変わる）。
2. **受け皿導線の実機確認**: 招待→着地→1通目、端末リンク、履歴転送は実装とテストが済んでいるが、実機2台での確認が未実施 [COMPARISON.md]。波は予告なく来るため、「その日に直す」は間に合わない。

### 5.2 作る（優位を強める順）

1. **シグナルポーリングの削減**（[COST_MODEL.md](COST_MODEL.md) 第7節レバー1）: 費用の支配項はメッセージ量ではなく「オンラインであること」のポーリングである。ルームが立つ時間を会話が開かれている間に限ることで、限界費用は軽い利用で $0.043 → $0.016/MAU/月まで下がる [COST_MODEL.md 第4.3節]。これは優位の文 (2)「中心の請求が伸びない」を数値で固くする唯一の実装であり、機能追加より優先する。
2. **アンテナの段階 A/B の実装判断**（[ANTENNA_PLAN.md](ANTENNA_PLAN.md)）: 自分の複数端末と連絡先の範囲で、端末同士の預かりを正式化する。中心の縮小をさらに進め、優位の文 (1) を強める。段階 C（不特定の公開アンテナ）は本書の優位には不要であり、引き続き別判断とする。
3. **波の日の即応パッケージ**: 事件が起きたときに「逃げ先」として指名されるための公開面（[COMPARISON.md](COMPARISON.md) の検証可能な比較、移行ガイド、インポート導線）を、平常時に完成させておく。新しい機能ではなく、既にあるものの発見可能性の固定である。

### 5.3 消す（主張の側）

1. **「量子耐性」「P2P」を単独の売りにする言い方**: 候補1・2の通り反証可能であり、看板と実態の一致を損なう。README の "Why Breeze?" 表は、項目を「登録なし」「サーバー信頼ゼロ」等の事実に置く現在の形から、構造（所有と費用）へ重心を移すことを検討する。具体的な文案の変更は別作業とするが、方向は本書が定める: 売りは機能名ではなく「誰が所有し、誰が払うか」である。
2. **「Signal より安全」類の含意**: 外部監査と実績の差がある間は、暗号の優劣を主張しない（候補11）。[COMPARISON.md](COMPARISON.md) の正直な書き方を公開面の標準とする。

### 5.4 後回し（優位の方向と逆、または無関係）

1. **SPQR 級の継続 PQ リキーイング**: Signal との差は事実だが、優位の構成要素ではない（候補1）。衛生水準の範囲で、余力があれば。
2. **チャンネル／公開コミュニティ・公式アカウント基盤**: 運営の厚みは「中心を持つ」方向であり、本書の優位と逆向き。受け皿の完成（SHARE_PLAN 段階7）が済んだ後でも、やる理由は優位からは出てこない。
3. **日常プラットフォーム化（決済・サービス連携）**: mi の方針（本体無料・寄付のみ）の外であり、LINE の土俵に上がる行為。やらない。

### 5.5 入口の設計 — 最初の利用者をどう得るか

優位が「待てること」である以上、入口は「波の受け皿」と「波がなくても移る小集団」の二本立てになる。集団の定義は SHARE_PLAN 第3節を正本とし、本書は優位との接続だけを書く。

- **集団A（事件の受け皿）**: 波の日に必要なのは広告ではなく完成度である — 既定インスタンスが生きている、配布物が新しい、招待が摩擦なく通る、履歴を持って移れる。この4点が 5.1 と 5.2-3 の主題であり、これ以上の入口施策（大規模な宣伝）は費用構造の優位と両立しない（宣伝費は「誰かが払う」費用そのもの）。
- **集団B（電話番号を出したくない層）**: Signal の番号の壁で止まる層。`@alias@relay` の到達可能性と、履歴インポートのある受け皿であることが入口になる。
- **集団C（自分の置き場所を持ちたいコミュニティ）**: 優位の文そのものが入口になる唯一の集団 — 「自分たちのリレーを立てれば、誰の許可もなく、自分たちの費用だけで存在し続けられる」。自己ホストの手順の平易さがそのまま転換率を決める。
- **測り方**: 追跡を入れない製品の原則を守り、SHARE_PLAN 第7節の代理指標（既定リレーのリクエスト数と登録 ID 数の推移、配布物のダウンロード数、公開リレーの総数）でだけ測る。個人を追う計測は集団A の移行理由そのものを壊すので入れない。

### 5.6 優位が無効になる条件（反証可能性）

本書の優位は、以下のいずれかが起きれば再審査とする:

1. Signal が基盤の聯邦化・自己ホスト相互接続を公式に採用したとき（文 (ii) の Signal に対する差が消える）。
2. SimpleX が収益化の圧力から自由な存立（例: 財団化）に移行し、かつ日常の完成度で Breeze に並んだとき。
3. 既定インスタンスの復旧が長期に実現せず、受け皿が閉じたまま波が2回以上通過したとき（優位は「潜在」のまま陳腐化する）。
4. 実機検証で受け皿導線（招待・通話・転送）に移行を止める欠陥が見つかり、修正の見通しが立たないとき。
