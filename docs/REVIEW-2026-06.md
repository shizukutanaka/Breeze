# Breeze — State Review & Improvement Spec (2026-06-20)

**Scope:** post Phase-2 (items 86–92) snapshot. Strengths / weaknesses / prioritized
improvements, with the concrete changes implemented in this pass.
**Baseline:** index.html 13,398 · _worker.js 3,167 · sw.js 163 · src/crypto/ 9 modules ·
14 test suites (729 tests) · validate.sh 34/34.

## 1. Strengths (長所)

| # | Strength | Evidence |
|---|----------|----------|
| S1 | **Tested crypto core as source of truth** | `src/crypto/{ratchet,group,atrest,franking,ktlog,negotiate,pow,fingerprint,bytes}.js`, 735 mutation-verified tests. Wire formats + security sequencing live in one place. |
| S2 | **Authenticated E2E protocol stack** | Double Ratchet (1:1), X3DH v5 with mandatory pre-key signature verify (`initiatorHandshake` *throws* on bad sig), group sender-key hash ratchet + epoch revocation, Sealed Sender. |
| S3 | **Defense-in-depth beyond the ratchet** | key commitment (invisible-salamander fix), message franking (abuse reports without breaking E2E), key-transparency log (rollover detection), PoW anti-spam, replay LRU + IDB dedup. |
| S4 | **Hardened at-rest module** | `atrest.js`: AAD domain-separation + per-slot context binding (relocation protection), PBKDF2 DoS guard on the attacker-controllable `iter`. |
| S5 | **Disciplined rollout** | every protocol change behind a `CONFIG` flag with a v3/v4 read path; worker changes additive + backward-compatible. |
| S6 | **Low supply-chain risk** | single-file deploy, no build step, no npm runtime deps, vanilla JS. |
| S7 | **Governance + i18n** | CLAUDE.md/AGENTS.md enforce `t()`/`esc()`/`_DOM`/`postAPIRaw`; EN+JA parity (~1,000 keys); validate.sh quality gate. |

## 2. Weaknesses (短所)

| # | Weakness | Risk | Source |
|---|----------|------|--------|
| W1 | **Inline ↔ module divergence.** index.html keeps inline crypto copies that drift from the tested `src/crypto/` modules. | Untested live code; security fixes land in modules but not the runtime. | INTEGRATION.md preamble |
| W2 | **Phase 2c at-rest regression (self-inflicted).** Item 92 added weaker duplicate `wrapKeyAtRest`/`unwrapKeyAtRest` to `ratchet.js` + a divergent inline record format (`{wrapped,salt,iv,kdf:'pbkdf2-v1'}`) — **no AAD binding, no DoS guard** — instead of mirroring canonical `atrest.js`. | Two at-rest formats; weaker variant in the live path; redundant tests. | this review |
| W3 | **N1 — `dhRatchetStep` Nr bug (live).** Resets `sendCounter` but not `recvCounter`; the first inbound message after a DH step is misread as a replay. | Silent message drop on the 3rd ratchet direction-flip. | INTEGRATION.md §1 |
| W4 | **AEAD desync (live).** Inline ratchet advances receive-chain state before AES-GCM auth; a corrupt injected ciphertext permanently desyncs the receive chain. | DoS until renegotiation. | INTEGRATION.md "Security notes" |
| W5 | **Pre-AES compression (live, I15).** Inline `encryptFor` deflates before AES-GCM (CRIME/BREACH class). | Length side-channel on compressible plaintext. | INTEGRATION.md §2 |
| W6 | **SPEC.md stale.** Dated R210; wrong line/endpoint counts; missing Phase 2 work. | Doc drift. | this review |
| W7 | **Most module work unwired.** X3DH v5 / group v5 / ktlog / franking / negotiate are tested but flags default OFF / not imported. | Capability gap between tested and shipped. | INTEGRATION.md §§3–8 |

## 3. Prioritized improvements (改善点)

1. **[HIGH · done here]** Reconcile Phase 2c at-rest onto canonical `atrest.js` (fix W2): remove the `ratchet.js` duplication, rewrite the inline mirror to the canonical record format with AAD per-slot context + DoS guard, route load via `isWrapped`/`loadKey`/`migrate` semantics.
2. **[HIGH · done here]** Fix N1 Nr reset in `dhRatchetStep` (fix W3): add `sess.recvCounter = 0` so the inline copy matches the tested module.
3. **[HIGH · deferred]** Port AEAD-desync fix into inline ratchet (W4) — needs a two-device pass; tracked in INTEGRATION.md.
4. **[MED · deferred]** Drop pre-AES compression (W5, I15).
5. **[MED · deferred]** Refresh SPEC.md (W6).

> Items 3–5 change the live message path and per INTEGRATION.md require a manual
> two-device test before landing; items 1–2 are verifiable against the tested
> module (atrest.test.js / x3dh.test.js) and are applied in this pass.

## 4. Implemented this pass

- **W2 fixed.** `src/crypto/ratchet.js` reverted to its pre-item-92 surface (group +
  X3DH only). The inline at-rest helpers in index.html now mirror `atrest.js`:
  record `{ v, kdf:'pbkdf2', hash, iter, salt, iv, ct }`, AAD `breeze-atrest-v1:<slot>`
  (slot = `keys` / `signing`), `iter` DoS guard (≤ 10,000,000), and
  `_atRestIsWrapped`/`_atRestLoadKey`/`_atRestMigrate` matching the module. `/keywrap`
  enable uses `migrate` (nested `wrapped`, plaintext `priv` removed); disable unwraps
  and restores plaintext. Redundant ratchet.test.js at-rest tests removed —
  `atrest.test.js` (20 tests) is the canonical coverage.
- **W3 fixed.** `dhRatchetStep` now resets `recvCounter` alongside `sendCounter`.
