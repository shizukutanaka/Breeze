## 4. Implemented this pass

- **W2 fixed.** `src/crypto/ratchet.js` reverted to its pre-item-92 surface (group +
  X3DH only). The inline at-rest helpers in index.html now mirror `atrest.js`:
  record `{ v, kdf:'pbkdf2', hash, iter, salt, iv, ct }`, AAD `breeze-atrest-v1:<slot>`
  (slot = `keys` / `signing`), `iter` DoS guard (≤ 10,000,000), and
  `_atRestIsWrapped`/`_atRestLoadKey`/`_atRestMigrate` matching the module. `/keywrap`
  enable uses `migrate` (nested `wrapped`, plaintext `priv` removed); disable unwraps
  and restores plaintext. Redundant ratchet.test.js at-rest tests removed —
  `atrest.test.js` (20 tests) is the canonical coverage.
- **W3 fixed.** `dhRatchetStep` now resets `recvCounter` alongside `sendCounter`.

### Update (item 94)

- **W4 falsified.** Socratic claim: *"the inline ratchet advances `recvChainKey`/`recvCounter`
  and populates `skippedKeys` before the AES-GCM decrypt, so a forged ciphertext desyncs the
  chain."* Falsified by reading the persistence boundary: `getSession` → `dbGet` returns a
  fresh IndexedDB structured clone every call (no shared in-memory session), and `saveSession`
  runs **only after a successful decrypt** (and the skipped-key hit). On a decrypt throw the
  mutated `sess` is never written back, so IDB keeps the pre-message state and the next genuine
  message re-derives correctly. The ordering is fragile but **not** a live desync. Left as-is;
  the clean ordering lands with the G4 ratchet-module port (tested).
- **W5 fixed.** `encryptFor` no longer compresses plaintext before AES-GCM (CRIME/BREACH-class
  length side-channel, I15). Messages are sent uncompressed (flags bit0 = 0); the receive path
  retains decompression for legacy flag-set messages, so the change is wire-compatible in both
  directions. Matches `src/crypto/ratchet.js` (`frameEncrypt` default `compressMin: Infinity`).

### Update (item 95 — Trusted Types enforcement, Phase 2d)

**Research source.** Qiita and Zenn articles validate a phased Trusted Types + CSP rollout:
the Zenn team's own production CSP introduction (`team_zenn/introduced-csp-to-zenn`) shows
the default-policy safety-net pattern; multiple Qiita/MDN references confirm
`require-trusted-types-for 'script'` covers `innerHTML` / `insertAdjacentHTML` / `outerHTML`
/ `iframe.srcdoc` / `document.write` / `eval` / `new Function` / `setTimeout(string)`.

**Audit.** Breeze has 98 raw HTML sinks (88 `innerHTML` + 6 `insertAdjacentHTML` + 4
`outerHTML`, all from `renderReactions`) and **zero script-creating sinks** — no `eval`, no
`new Function`, no `setTimeout(string)`, no dynamic `<script>` injection, no `iframe srcdoc`,
no `document.write`. So a single `createHTML` policy covers the whole attack surface.

**Fix.**
- Register a **`default` Trusted Types policy** alongside the existing named
  `breeze-sanitizer`. Both call the same `sanitize()` function (DOMParser + tag/attr
  allowlist + `javascript:` href strip). The default policy is the browser's safety net
  for any raw `el.innerHTML = stringValue` site, so the 98 untargeted sinks become
  sanitized transparently rather than throwing SecurityError under enforcement.
- Add `default` to the `trusted-types` directive in BOTH `_headers` and the inline
  `<meta http-equiv="Content-Security-Policy">`, and add
  `require-trusted-types-for 'script'` to enforce. Browsers without TT support (Firefox,
  Safari) silently ignore the directive; behavior is unchanged for them.
- Hot-path cost: the sanitizer's fast path (`if (!/</.test(html)) return html`) returns
  in one regex test for plain text — which is the common case after `esc()`. Only HTML
  containing `<` triggers the DOMParser walk.

### Update (item 96 — Service Worker cache hardening)

**Research sweep (round 2).** Audited the surfaces a Qiita/Zenn sweep flagged (Cloudflare
KV cost, WebRTC reconnection, IndexedDB perf, SW/PWA caching) against the code. Most were
already mature — worker presence cache + 5-min KV write batching (`handlePresence`), the
lossless +1ms poll cursor (`handleMsgSend`/`handleMsgPoll`), the shell-preserving SW cache
trim, and a complete PWA manifest (share_target / protocol_handlers / shortcuts /
edge_side_panel). So the prior roadmap's Phase-3 items (KV pressure, same-ms poll loss) are
**already addressed**. Net: one concrete gap remained.

- **SW `Cache.put()` pitfall fixed.** Both fetch-handler put sites guarded with `if (resp.ok)`,
  but `resp.ok` is **true for 206 Partial Content**, and `Cache.put()` throws on a partial
  response; the put was also unawaited/uncaught, so a 206 (range request) or a
  `QuotaExceededError` (storage full) became an unhandled rejection. New DRY `cachePut()`
  helper caches only `status === 200 && type === 'basic'` responses (skips 206, opaque, CORS)
  and wraps the write in `.catch(() => {})`. 5 new `tests/sw.test.js` cases via the existing
  mocked-global harness.

### Update (item 97 — modal a11y + button i18n)

**Research sweep (round 3 — accessibility).** Audited modals/menus against the ARIA APG
dialog pattern and live-region guidance. Breeze already uses native `<dialog>` +
`showModal()` (role=dialog, aria-modal, focus trap, ESC, focus-restore for free), a
`role=menu` context menu with arrow-key nav, and an `aria-live` SR announcer — so the
structural pieces were present. Two gaps:

- **Accessible name missing.** `showPrompt`/`showConfirm` dialogs had no `aria-labelledby`
  (nameless dialog to a screen reader) and the prompt `<input>` had only a placeholder.
  Fixed: unique `titleId` on the title, `dlg.aria-labelledby = titleId`, input
  `aria-labelledby = titleId`.
- **Hardcoded English buttons.** "Cancel"/"OK"/`aria-label="Cancel"` bypassed `t()`. Added
  `cancel`/`ok` i18n keys (EN+JA); buttons now use `t('cancel')` / `opts.okText || t('ok')`;
  dropped the redundant aria-label (translated text is the accessible name). 33 call sites.

### Update (item 107 — NEW FEATURE: idle auto-lock, Socratic-derived)

**Socratic feature design.** Q: the most common real-world attack on a messenger isn't the
crypto — it's reading an unlocked, unattended screen; does Breeze cover it? It has `/lock`
and `/lock auto`, but `/lock auto` only fires on tab hide — staying on the tab while away
from the desk leaves everything readable. A: add an **idle auto-lock**. `/lock idle <1–120>`
arms an inactivity timer (off/0 disables; needs a lock password); activity events
(`pointerdown`/`keydown`/`touchstart`/`wheel`/`mousemove`, all passive + AbortController-scoped)
reset `_idleLockLast`; a 15 s interval calls the existing `showLockScreen()` past the
threshold. Complements `/lock auto`; reuses the hardened lock path (PBKDF2 + brute-force
backoff + focus trap), so no new crypto/attack surface. Status in `/security`; new i18n keys
(EN+JA); `/lock reset` clears it.

### Update (item 106 — localized relative time via Intl.RelativeTimeFormat)

**Research sweep (round 12 — relative time i18n).** Qiita/Zenn `Intl.RelativeTimeFormat`:
the locale-complete way to render "5 minutes ago"/"5 分前"/"yesterday"/"昨日". The offline
chat header hardcoded `'5m ago'`/`'3h ago'`/`'2d ago'` and the word `'Offline'`. Added a
cached `relTime(diffMs)` helper (`Intl.RelativeTimeFormat(LANG, {numeric:'auto'})`,
sub-minute → `t('justNow')`), wired it into the last-seen line, and localized the status
word (`statusOffline`/`justNow` keys, EN+JA). Left the width-sensitive contact-list compact
stamps (`5m`/`3h`/`2d`) for a separate pass.

### Update (item 105 — dynamic dialog buttons localized; focus-visible verified sound)

**Research sweep (round 11 — focus indicators).** Began on `:focus-visible`/`outline:none`.
Audit found Breeze **already correct**: a global `:focus-visible` outline covers buttons, and
inputs with `outline:none` are compensated by `input:focus`/`textarea:focus` box-shadow rings
— keyboard focus is never lost (verified non-issue, no edit). Applied the i18n/a11y theme to a
real gap instead: dynamically-built dialogs (forward, paste-image, dead-drop, link-open)
hardcoded English buttons (`Forward`/`Send`/`Cancel`/`Open`) that bypass the static
`data-i18n` pass. Added `forward`/`open` keys (EN+JA; `send`/`cancel` existed) and localized 7
buttons + the `Forward to:` heading via inline `t()`.

### Update (item 104 — localize title tooltips + name icon-only controls)

**Research sweep (round 10 — title attribute a11y).** Qiita/Zenn: `title` is unreliable as
an accessible name (not all AT exposes it, keyboard-inaccessible, HTML-LS discourages it for
tooltips) — icon-only controls relying on `title` are effectively unnamed. Breeze had 8
hardcoded English `title=` tooltips and no `data-i18n-title` handler (JA users saw English),
and the 📎-attach + 😀-emoji controls named themselves only via `title`/an English
`aria-label`. Added a `data-i18n-title` handler + 8 tooltip keys (EN+JA, incl. a function
key `ttDisappearsIn(label)`); localized the 4 static + 4 dynamic tooltips; gave the two
icon-only controls reliable localized `aria-label`s.

### Update (item 103 — localize input aria-labels + revive dead placeholder)

**Research sweep (round 9 — form a11y).** Qiita/Zenn form-accessibility + WCAG 2.2: a
control needs a programmatic accessible name; a `placeholder` is not one. Breeze's inputs
all had `aria-label` — but **hardcoded English** (no `data-i18n-aria` equivalent to the
`data-i18n-ph` mechanism), so JA screen-reader users heard English field names. Added a
`data-i18n-aria` apply handler + 5 concise aria keys (EN+JA); converted the 5 static inputs.
Also found the forward-dialog filter's `data-i18n-ph` was **dead** (the node is built via
innerHTML after the one-time handler ran) — it had no placeholder and no accessible name;
set both inline via `t()`.

### Update (item 102 — decoding="async" on display images + alt i18n)

**Research sweep (round 8 — image loading).** Zenn `decoding="async"` deep-dives: `loading`
controls when to fetch, `decoding` controls when to decode; `decoding="async"` keeps decode
off the main thread and pairs with `loading="lazy"`. Audit: every below-fold `<img>` already
had `loading="lazy"` but **none had `decoding="async"`** — so each image still decoded
synchronously on the main thread when scrolled into view, janking the scroll lazy-loading was
meant to smooth. Added `decoding="async"` to all display images (message image, OGP
cover/favicon/thumb, compose + select previews, lightbox big image). Also fixed a hardcoded
`img.alt = 'Full size image'` on the lightbox → `t('fullSizeImage')` (EN/JA).

### Update (item 101 — content-visibility on message rows)

**Research sweep (round 7 — CSS rendering performance).** Qiita `content-visibility` +
CSS Containment guides: `content-visibility: auto` skips layout+paint of off-screen
elements until they scroll into view (biggest win on long lists), paired with
`contain-intrinsic-size` to reserve height. The contact-list row `.contact` already used
this (`auto 60px`); the message list `.msg` — the longer, more-scrolled list (up to
MSG_DOM_LIMIT = 200 nodes) — did not (only `contain: content`). Added
`content-visibility: auto; contain-intrinsic-size: auto 44px` to `.msg` (the `auto` keyword
remembers each row's real size after first render). Added a print guard
(`@media print .msg { content-visibility: visible !important }`) so `/print` still renders
all messages — `content-visibility: auto` otherwise skips off-screen content when printing.
Ctrl+F find-in-page is unaffected (the property keeps content findable by design).

### Update (item 100 — crash-overlay i18n + ghost key fix)

**Research sweep (round 6 — global error handling).** Breeze already has `window` `error` +
`unhandledrejection` handlers (flood limit, fatal-error crash overlay, audit log) — mature.
Auditing the failure-path UI itself found: (1) a **ghost key bug** — the init-failure overlay
used `t('uiError') || 'Something went wrong'`, but no `uiError` key exists and `t()` falls
back to the key string, so it rendered the literal title **"uiError"**; fixed to
`t('crashTitle')`. (2) Both crash overlays had **hardcoded English** (title/body/Reload/Clear
cache/Clearing) — a JA user hits English at the worst moment; added `crashTitle`/`crashBody`/
`crashClearCache` (EN+JA), reused `uiReload`/`clearing`. (3) Avoided a duplicate `clearing`
key. The "last line of defense" UI is now itself localized.

### Update (item 99 — passive listeners on every observer-only touch/scroll)

**Research sweep (round 5 — performance).** Qiita performance-tuning guides plus
`kyntk/5c16846a…` reiterate that a touch/scroll listener without `{ passive: true }`
blocks scroll on the main thread (Chrome logs "Added non-passive event listener to a
scroll-blocking event"). Audit: 13 touch/scroll listeners — 9 already declared `passive`
(2 legitimately `false` for `preventDefault` paths: pinch-zoom + reaction-picker
double-tap). 4 observer-only sites omitted the option (visualViewport scroll, two image
lightbox `touchend` sites, and the message-list `scroll` → FAB toggle). Added
`{ passive: true }` to all four; no logic change. Every touch/scroll listener in the app
now explicitly declares its intent.

### Update (item 98 — peer-heartbeat interval leak)

**Research sweep (round 4 — memory leaks).** Audited every `setInterval` against its
teardown. Most are tracked in `_intervals` (cleared on account switch) or are
lifecycle-scoped (`_callTimerInterval`, `_recTimer`, cleared at call/recording end). One
genuine leak: the account-switch teardown (`_messengerCleanup`) cleared each peer's
`_healthTimer` but **not** its sibling `_heartbeat`. `_heartbeat` is otherwise cleared only
by the connectionstatechange handler — and `pc.close()` does not fire that event (per
spec) — so after every account switch each peer's heartbeat kept firing against a closed
DataChannel, pinning the old `peerState` graph against GC. Fixed by clearing `p._heartbeat`
in the teardown loop (symmetric with `_healthTimer`). Inspection-verified (no unit harness
for the inline WebRTC peer path).
