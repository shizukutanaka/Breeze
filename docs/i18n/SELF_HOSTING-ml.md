ഒരു Breeze റിലേ പ്രവർത്തിപ്പിക്കാൻ രണ്ട് വഴികളുണ്ട്:

1. **സെൽഫ്-ഹോസ്റ്റ് ചെയ്തത് (Node + Docker)** — നിങ്ങളുടെ സ്വന്തം മെഷീനിലോ
   VPS-ലോ ഉള്ള റിലേ: ഒരു കണ്ടെയ്നർ, ഒരു ഡാറ്റ വോളിയം, രജിസ്ട്രേഷൻ സ്ഥിരമായി
   അടച്ചിരിക്കുന്നു. റിലേ നിങ്ങൾക്കും നിങ്ങളുടെ ആളുകൾക്കും വേണ്ടിയാണെങ്കിൽ ഇവിടെ നിന്ന് തുടങ്ങുക.
2. **Cloudflare** — Cloudflare-ന്റെ സൗജന്യ ടയറിലെ ഔദ്യോഗിക ശൈലിയിലുള്ള വിന്യാസം
   (Breeze തന്നെ പ്രവർത്തിപ്പിക്കുന്ന റിലേ). പരിപാലിക്കാൻ ഒരു സെർവർ ഇല്ലാതെ
   ഒരു പൊതു റിലേ വേണമെങ്കിൽ അവിടെ നിന്ന് തുടങ്ങുക.

രണ്ടും ഒരേ ഹാൻഡ്‌ലർ കോഡ് പ്രവർത്തിപ്പിക്കുന്നു; ഏതുവിധേനയും ഒരു റിലേ എന്നത് ലളിതവും
പരസ്പരം മാറ്റാവുന്നതുമായ ഒരു മെയിൽബോക്സാണ്, കൂടാതെ എല്ലാ ക്ലയന്റും എല്ലാ
റിലേയുമായും പ്രവർത്തിക്കുന്നു.

## Docker ഉപയോഗിച്ച് സെൽഫ്-ഹോസ്റ്റ് ചെയ്തത്

```bash
# 1. Get the code
git clone https://github.com/shizukutanaka/Breeze.git && cd Breeze

# 2. Start it, with your own Breeze ID admitted (see "Registration"
#    below for how to find it — you can also start closed-to-everyone
#    and add IDs later)
BREEZE_ALLOWLIST=<your Breeze ID> docker compose up -d

# 3. Watch the first-boot log — it prints your relay identity
#    fingerprint; write it down (see "Relay identity")
docker compose logs breeze
```

റിലേ കണ്ടെയ്നറിനുള്ളിൽ പോർട്ട് 8787-ൽ പ്ലെയിൻ HTTP നൽകുന്നു.
**അതിന് മുന്നിൽ ഒരു റിവേഴ്സ് പ്രോക്സിയിൽ TLS അവസാനിപ്പിക്കുക** (Caddy, nginx,
Traefik, ഒരു Cloudflare Tunnel, …): ബ്രൗസറുകൾ ഒരു റിലേയെ
HTTPS/WSS വഴി മാത്രമേ ഉപയോഗിക്കൂ. നിങ്ങൾ അങ്ങനെ ചെയ്യുമ്പോൾ, `docker-compose.yml`-ൽ
`TRUST_PROXY: "true"` എന്ന് സജ്ജമാക്കുക, അങ്ങനെ നിരക്ക് പരിധി യഥാർത്ഥ ക്ലയന്റ്
വിലാസത്തെ അടിസ്ഥാനമാക്കും — അത്തരമൊരു പ്രോക്സി ഇല്ലാതെ അത് ഒരിക്കലും സജ്ജമാക്കരുത്, കാരണം അത്
വിശ്വസിക്കുന്ന ഹെഡർ, പ്രവേശനത്തിലേക്ക് നേരിട്ട് എത്താൻ കഴിയുന്ന ആർക്കും വ്യാജമായി ഉണ്ടാക്കാം.

ഡാറ്റ വോളിയത്തിനെതിരെ കൃത്യമായി **ഒരു** കണ്ടെയ്നർ പ്രവർത്തിപ്പിക്കുക: നിരക്ക്
പരിധി നിശ്ചയിക്കുന്നയാൾ ഓരോ പ്രക്രിയയ്ക്കും മെമ്മറിയിലാണ്, ഓരോ മെയിൽബോക്സിന്റെയും പ്രവർത്തനങ്ങൾ
ആ പ്രക്രിയയ്ക്കുള്ളിൽ ക്രമീകരിച്ചിരിക്കുന്നു, അതിനാൽ രണ്ടാമത്തെ പകർപ്പിന്
ഈ സവിശേഷതകളൊന്നും ഉണ്ടാകില്ല. ഒരൊറ്റ പ്രക്രിയയ്ക്ക് വലിയൊരു മെഷീൻ നൽകി സ്കെയിൽ ചെയ്യുക.

### രജിസ്ട്രേഷൻ: സ്ഥിരമായി അടച്ചിരിക്കുന്നു

ഇന്റർനെറ്റിൽ ആർക്കും രജിസ്റ്റർ ചെയ്യാൻ കഴിയുന്ന ഒരു സെൽഫ്-ഹോസ്റ്റ് റിലേ,
ഔദ്യോഗിക റിലേയുടെ പരിധികൾ നിയന്ത്രിക്കാൻ നിലനിൽക്കുന്ന സ്പാം/ദുരുപയോഗ സാമ്പത്തികശാസ്ത്രത്തെ വീണ്ടും സൃഷ്ടിക്കും,
അതിനാൽ **Docker പാക്കേജിംഗ് അടച്ച നിലയിലാണ് വരുന്നത്**: കമ്പോസ്
ഫയൽ ഒരു `REGISTRATION_ALLOWLIST` (ഒരുപക്ഷേ ശൂന്യമായത്) കൈമാറുന്നു, കൂടാതെ
അതിലുള്ള Breeze ID-കൾക്ക് മാത്രമേ *അക്കൗണ്ടുകൾ സൃഷ്ടിക്കാൻ* കഴിയൂ (ആദ്യത്തെ പ്രീകീ
അപ്‌ലോഡ്). രജിസ്ട്രേഷൻ അടയ്ക്കുന്നത് ഇതിനകം റിലേയിൽ വസിക്കുന്ന ആളുകളെ ഒരിക്കലും ബാധിക്കില്ല
— അവരുടെ അപ്‌ലോഡുകളും നിക്ഷേപങ്ങളും കൂടിക്കാഴ്ചകളും പോളുകളും
ഗേറ്റ് ചെയ്തിട്ടില്ല — രജിസ്ട്രേഷൻ തുറക്കുന്നത് വ്യക്തമായ ഒരു തിരഞ്ഞെടുപ്പാണ്, ഒരിക്കലും
സ്ഥിരസ്ഥിതിയല്ല.

- **നിങ്ങളുടെ Breeze ID** എന്നത് നിങ്ങളുടെ ക്ഷണ ലിങ്കിലെ 12-അക്ഷര ഐഡന്റിഫയറാണ്
  (അതിന്റെ `pub` മൂല്യത്തിന്റെ ആദ്യത്തെ 12 അക്ഷരങ്ങൾ). നിങ്ങൾ ക്ഷണിക്കുന്ന ഓരോ വ്യക്തിയോടും അവരുടേത് അതേ
  രീതിയിൽ ചോദിക്കുക — ID എന്നത് കോൺടാക്റ്റുകൾ ഇതിനകം കൈമാറുന്ന ഒരു പൊതു ഐഡന്റിഫയറാണ്,
  രഹസ്യമല്ല.
- **ആളുകളെ പ്രവേശിപ്പിക്കാൻ** അവരുടെ ID-കൾ പട്ടികപ്പെടുത്തുക: നിങ്ങളുടെ ഷെല്ലിൽ
  `BREEZE_ALLOWLIST=id1,id2,…` എന്ന് സജ്ജമാക്കുക അല്ലെങ്കിൽ `docker-compose.yml`-ന് അടുത്തുള്ള ഒരു `.env` ഫയലിൽ,
  എന്നിട്ട് വീണ്ടും `docker compose up -d` ചെയ്യുക.
- **ഇപ്പോൾ തുടങ്ങുക, പിന്നീട് പ്രവേശിപ്പിക്കുക**: `BREEZE_ALLOWLIST` സജ്ജമാക്കാത്തപ്പോൾ, റിലേ
  എല്ലാവർക്കും അടച്ച നിലയിൽ പ്രവർത്തിക്കുന്നു — ബൂട്ട് ലോഗ് അങ്ങനെ പറയുന്നു — നിങ്ങൾ ID-കൾ ചേർക്കുന്നത് വരെ ആർക്കും
  രജിസ്റ്റർ ചെയ്യാൻ കഴിയില്ല.
- **തുറന്ന റിലേ** (ആർക്കും രജിസ്റ്റർ ചെയ്യാം): `docker-compose.yml`-ൽ
  `REGISTRATION_OPEN: "1"` എന്നതിന്റെ കമന്റ് നീക്കം ചെയ്യുക. നിങ്ങൾ അങ്ങനെ ചെയ്താൽ ദുരുപയോഗ സാമ്പത്തികശാസ്ത്രം നിങ്ങളുടേതാണ്.

### ഉപയോഗ ക്വാട്ട: നിങ്ങളുടെ സ്വന്തം റിലേയിൽ അത് ഓഫ് ചെയ്യുക

വർക്കർ ഒരു **ന്യായമായ-ഉപയോഗ ഉപയോഗ ക്വാട്ട** പ്രവർത്തനക്ഷമമാക്കിയാണ് വരുന്നത്: ഓരോ
മെയിൽബോക്സിനും, പരമാവധി 10,000 നിക്ഷേപങ്ങൾ/ദിവസം, 200,000/മാസം (ഒരു നിക്ഷേപം എന്നത്
ഒരു പൂർണ്ണ ഡെലിവറി സൈക്കിളാണ് — നയത്തിനും സംഖ്യകൾക്കും `docs/COST_MODEL.md` §10 കാണുക). ആ ചട്ടക്കൂട് *പങ്കിട്ട സ്ഥിര
റിലേയ്ക്ക്* വേണ്ടിയാണ് നിലനിൽക്കുന്നത്, അത് ഒരു സൗജന്യ പ്രവേശനമായി പ്രവർത്തിപ്പിക്കുന്നു, അതിന്റെ വേരിയബിൾ ചെലവുകൾ
ഓപ്പറേറ്റർക്ക് അല്ലെങ്കിൽ എല്ലാവർക്കും വേണ്ടി വഹിക്കേണ്ടി വരും. **നിങ്ങൾ
നിങ്ങൾക്കും നിങ്ങളുടെ ആളുകൾക്കും വേണ്ടി പ്രവർത്തിപ്പിക്കുന്ന ഒരു റിലേയിൽ, ആ ചട്ടക്കൂട് അർത്ഥശൂന്യമാണ് — അത്
അപ്രാപ്തമാക്കുക**:

```bash
USAGE_QUOTA_ENABLED=false
```

നിങ്ങളുടെ റിലേ അതിന്റെ പരിസ്ഥിതി വായിക്കുന്നിടത്ത് അത് സജ്ജമാക്കുക (ഷെൽ അല്ലെങ്കിൽ
`docker-compose.yml`-ന് അടുത്തുള്ള `.env`, Node പ്രക്രിയ പരിസ്ഥിതി,
അല്ലെങ്കിൽ Cloudflare Pages രഹസ്യങ്ങൾ). നിങ്ങൾ
ഒരു കമ്മ്യൂണിറ്റി റിലേ പ്രവർത്തിപ്പിക്കുകയും ഒരു ചട്ടക്കൂട് *ആഗ്രഹിക്കുകയും* ചെയ്താൽ രണ്ട് അയൽ നോബുകൾ ഉണ്ട്:
`USAGE_QUOTA_DAILY`, `USAGE_QUOTA_MONTHLY` എന്നിവ ക്യാപ്പുകൾ വീണ്ടും ട്യൂൺ ചെയ്യുന്നു.
പ്രധാനപ്പെട്ട കുറിപ്പുകൾ:

- മെയിൽബോക്സുകൾ Durable
  Objects-ൽ (`MAILBOX_BACKEND=do`, ഈ ഹോസ്റ്റിലെ സ്ഥിരസ്ഥിതി) വസിക്കുമ്പോൾ മാത്രമേ ക്വാട്ട നടപ്പിലാക്കൂ; KV
  ബാക്കെൻഡിൽ ഇത് രേഖപ്പെടുത്തിയ ഒരു നോ-ഓപ്പാണ്.
- ക്യാപ്പിന് ശേഷം, അയയ്ക്കുന്നവർക്ക് നിശബ്ദമായി ഉപേക്ഷിക്കുന്നതിന് പകരം വ്യക്തമായ ഒരു `429 USAGE_QUOTA_EXCEEDED`
  (വിൻഡോയും അതിന്റെ പരിധിയും സഹിതം) ലഭിക്കുന്നു — സന്ദേശം
  അയയ്ക്കുന്നയാളുടെ ഔട്ട്ബോക്സിൽ തുടരുന്നു, സ്വീകർത്താവ്
  P2P വഴിയും മറ്റേതെങ്കിലും ഹോം റിലേ വഴിയും എത്തിച്ചേരാവുന്ന നിലയിൽ തുടരുന്നു.

### റിലേ ഐഡന്റിറ്റി

ആദ്യ ബൂട്ടിൽ റിലേ *ഡാറ്റ വോളിയത്തിനുള്ളിൽ* ഒരു സ്ഥിരമായ Ed25519 ഐഡന്റിറ്റി കീ
സൃഷ്ടിക്കുകയും ലോഗിൽ അതിന്റെ ഫിംഗർപ്രിന്റ് അച്ചടിക്കുകയും ചെയ്യുന്നു:

```
relay identity: NEW key generated — fingerprint 3F2A 9C41 …
```

ഫിംഗർപ്രിന്റ് *നിങ്ങളുടെ* റിലേയെ തിരിച്ചറിയുന്നു: അത് നിങ്ങളുടെ ഉപയോക്താക്കൾക്ക്
ബാൻഡിന് പുറത്ത് (നേരിട്ട്, മറ്റൊരു ചാനൽ വഴി) നൽകുക, അങ്ങനെ അവർക്ക് തങ്ങൾക്ക് നൽകിയ റിലേ
നിങ്ങൾ പ്രവർത്തിപ്പിക്കുന്നതാണെന്ന് തിരിച്ചറിയാൻ കഴിയും. അതേ ഫിംഗർപ്രിന്റ്
എല്ലാ ബൂട്ടിലും അച്ചടിക്കുന്നു; അത് എപ്പോഴെങ്കിലും മാറിയാൽ, ഡാറ്റ വോളിയം
മാറ്റിസ്ഥാപിച്ചു — ഉപയോക്താക്കളോട് പുതിയതിനെ വിശ്വസിക്കാൻ പറയുന്നതിന് മുമ്പ് അന്വേഷിക്കുക.

ക്ലയന്റുകൾ ഈ കീ സ്വയം പരിശോധിക്കുകയും പിൻ ചെയ്യുകയും ചെയ്യുന്നു (ഘട്ടം-2 ഘട്ടം 4): ആദ്യ
ബന്ധത്തിൽ ഒരു ക്ലയന്റ് കീ ഉപയോഗിച്ച് ഒപ്പിടാൻ റിലേയെ വെല്ലുവിളിക്കുന്നു
(`/api/relay/attest`), പരിശോധിച്ച കീ അക്കൗണ്ടിനൊപ്പം സംഭരിക്കുന്നു, കൂടാതെ
തുടർന്നുള്ള എല്ലാ സെഷനിലും വീണ്ടും പരിശോധിക്കുന്നു. ക്ലയന്റ് കാണിക്കുന്ന ഫിംഗർപ്രിന്റ്
(`/security`-ക്ക് കീഴിൽ, ആദ്യ പിന്നിലെ ടോസ്റ്റിലും) അതേ
കീയിൽ നിന്നാണ് ഉരുത്തിരിഞ്ഞത് — അത് മുകളിലുള്ള ബൂട്ട്-ലോഗ് വരിയുമായി താരതമ്യം ചെയ്യുക. കീ
എപ്പോഴെങ്കിലും മാറിയാൽ, ക്ലയന്റുകൾ **റിലേയുമായി സംസാരിക്കുന്നത് നിർത്തുകയും** ഉപയോക്താവിന്
മുന്നറിയിപ്പ് നൽകുകയും ചെയ്യുന്നു; അവ ഒരിക്കലും നിശബ്ദമായി വീണ്ടും പിൻ ചെയ്യില്ല. ഫിംഗർപ്രിന്റ് മാറ്റത്തെ ഒരു
തകർച്ച സംഭവമായി കണക്കാക്കുക: ഘട്ടം 4-ൽ ആപ്പിൽ "പുതിയ കീയെ വിശ്വസിക്കുക" എന്ന ബട്ടൺ ഇല്ല,
അതിനാൽ യഥാർത്ഥ വോളിയം നഷ്ടത്തിന് ശേഷം നിങ്ങളുടെ ഉപയോക്താക്കൾ അവരുടെ അക്കൗണ്ടിനായി ആപ്പിന്റെ സംഭരിച്ച ഡാറ്റ
മായ്‌ക്കുകയും ആദ്യ ബന്ധത്തിൽ വീണ്ടും പിൻ ചെയ്യുകയും വേണം —
പുതിയ ഫിംഗർപ്രിന്റ് ആദ്യം ബാൻഡിന് പുറത്ത് പ്രഖ്യാപിക്കുക, അല്ലെങ്കിൽ അവർക്ക് നിങ്ങളുടെ പുതിയ കീയെ ആക്രമണകാരിയുടെ കീയിൽ നിന്ന്
വേർതിരിച്ചറിയാൻ കഴിയില്ല.

### ബാക്കപ്പും പുനഃസ്ഥാപനവും

**ഡാറ്റ വോളിയമാണ് മുഴുവൻ റിലേ അവസ്ഥയും**: ഡയറക്ടറിയും മെയിൽബോക്സുകളും
റിലേ ഐഡന്റിറ്റി കീയും ഉൾക്കൊള്ളുന്ന ഒരു SQLite ഫയൽ.
ബാക്കപ്പ് ചെയ്യാൻ മറ്റൊന്നുമില്ല.

```bash
# Back up: copy the database out of the (stopped) container
docker compose stop
docker cp "$(docker compose ps -aq breeze)":/data/breeze-relay.db ./breeze-relay-backup.db
docker compose start

# Restore: copy the backup back in as /data/breeze-relay.db before
# starting, and the relay serves identically — same fingerprint.
docker compose stop
docker cp ./breeze-relay-backup.db "$(docker compose ps -aq breeze)":/data/breeze-relay.db
docker compose start
```

  `REGISTRATION_ALLOWLIST=id1,id2` എന്ന് സജ്ജമാക്കുക (അല്ലെങ്കിൽ
  എല്ലാവർക്കും അടച്ചതിനായി ഒരു ശൂന്യ മൂല്യം); `REGISTRATION_OPEN=1` അത് വ്യക്തമായി വീണ്ടും തുറക്കുന്നു.

## Cloudflare വിന്യാസം

### കുറഞ്ഞ വിന്യാസം ($0/മാസം, 5 മിനിറ്റ്)

```bash
# 1. Install Wrangler CLI
npm install -g wrangler

# 2. Login to Cloudflare
wrangler login

# 3. Deploy
wrangler pages deploy . --project-name=breeze

# 4. Create a KV namespace and declare it in wrangler.toml
wrangler kv:namespace create KV
# Copy the new namespace's ID and put it in wrangler.toml, replacing the
# id in the [[kv_namespaces]] section (binding = "KV"). Pages takes its
# bindings from wrangler.toml; a binding set only in the Dashboard is
# NOT applied while a wrangler.toml exists.
# Then deploy again so the binding takes effect:
wrangler pages deploy . --project-name=breeze

# 5. Visit your deployment's URL (https://<your-project>.pages.dev)
```

### ഓപ്ഷണൽ സവിശേഷതകൾ ചേർക്കൽ

#### പുഷ് അറിയിപ്പുകൾ (സൗജന്യം)

```bash
# Generate VAPID keys
npx web-push generate-vapid-keys

# Set secrets
wrangler pages secret put VAPID_PUBLIC_KEY
wrangler pages secret put VAPID_PRIVATE_KEY
```

#### TURN സെർവർ (നിയന്ത്രിത നെറ്റ്‌വർക്കുകൾക്കായി)

കോളുകളും റിലേ-മാത്രം (IP-മറയ്ക്കുന്ന) കണക്ഷനുകളും
നിയന്ത്രിത NAT-കളെ മറികടക്കുന്ന മാർഗമാണ് TURN. നിങ്ങളുടെ റിലേ ഏത് TURN ആണ് നൽകുന്നത് എന്നത് ഓപ്പറേറ്റർ എന്ന നിലയിൽ **നിങ്ങളുടെ** തിരഞ്ഞെടുപ്പാണ്
— Worker ക്രമത്തിൽ ശ്രമിക്കുന്നു:

```bash
# Option A: Cloudflare Calls ($0.05/GB, global anycast)
wrangler pages secret put TURN_KEY_ID
wrangler pages secret put TURN_KEY_API_TOKEN

# Option B: your own coturn (HMAC time-limited credentials — the Worker
# mints a 24h username/credential per registered user from the secret)
#   coturn: use-auth-secret, static-auth-secret=<same secret>
wrangler pages secret put TURN_URL      # turn:your-server:3478
wrangler pages secret put TURN_SECRET

# Option C: static credentials (metered.ca, Twilio, …)
wrangler pages secret put TURN_URL
wrangler pages secret put TURN_USERNAME
wrangler pages secret put TURN_CREDENTIAL

# Option D: No config → free Open Relay (20GB/month). This is a third
# party's PUBLIC quota, shared with every unconfigured relay — fine for
# a first run, not a foundation. Opt out explicitly and callers get
# STUN only (some restrictive-NAT calls will then fail, visibly):
wrangler pages secret put TURN_OPENRELAY_FALLBACK   # set to: false
```

**നിങ്ങൾ യഥാർത്ഥത്തിൽ എന്താണ് കോൺഫിഗർ ചെയ്തതെന്ന് പരിശോധിക്കുക:** `GET /api/health` ഫലപ്രദമായ
മോഡ് `turnProvider` ആയി റിപ്പോർട്ട് ചെയ്യുന്നു (`cloudflare` | `custom` | `static` |
`openrelay` | `none`). പഴയ `turn` ബൂളിയൻ
`TURN_URL`-നെ മാത്രമേ പ്രതിഫലിപ്പിക്കൂ, അതിനാൽ ശുപാർശ ചെയ്യുന്ന ഓപ്ഷൻ A-യ്ക്ക് അത് `false` എന്ന് വായിക്കുന്നു — `turnProvider` ഉപയോഗിക്കുക. ക്ലയന്റുകൾ `/security`-ൽ അതേ ദാതാവിനെ കാണിക്കുന്നു, അതിനാൽ
Open Relay ഫാൾബാക്കിലുള്ള ഒരു ഉപയോക്താവിന് ഒരു മൂന്നാം കക്ഷി തന്റെ
കോൾ മീഡിയ റിലേ ചെയ്യുന്നുവെന്ന് കാണാൻ കഴിയും (മെറ്റാഡാറ്റ മാത്രം — മീഡിയ തന്നെ DTLS-SRTP എൻക്രിപ്റ്റ് ചെയ്തതാണ്).

#### ഓത്ത് ശക്തിപ്പെടുത്തലും പ്ലെയിൻ റിലേ പാതയും

പ്രീകീ അപ്‌ലോഡുകൾ ഇപ്പോൾ ഒപ്പിടൽ ഉടമസ്ഥതയെ `prekey-owner:<userId>`-ൽ **TTL ഇല്ലാതെ** പ്രത്യേകമായി സംരക്ഷിക്കുന്നു. നിലവിലുള്ള ബണ്ടിൽ ഉടമസ്ഥത, ഒരു പകരം സ്വീകരിക്കുന്നതിന് മുമ്പ്, അടുത്ത അപ്‌ലോഡിൽ അലസമായി മൈഗ്രേറ്റ് ചെയ്യുന്നു. പുതിയ Ed25519 ബണ്ടിലുകളും ആ റെക്കോർഡ് സ്ഥാപിക്കുന്നു. കാലഹരണപ്പെട്ട പ്രീകീ ബണ്ടിലുകൾ വെട്ടിമാറ്റുമ്പോൾ ഈ റെക്കോർഡുകൾ സൂക്ഷിക്കുക: ബണ്ടിൽ കാലഹരണത്തിനായി കാത്തിരിക്കുന്നത് ഒരു പുതിയ ഉടമയെ അനുവദിക്കരുത്. റൊട്ടേഷന് മുമ്പത്തെ ഉടമ ഒപ്പിട്ട ഒരു അപ്‌ലോഡ് ആവശ്യമാണ്, അത് നിലവിലുള്ള അപ്‌ലോഡ് ഡൈജസ്റ്റിൽ പുതിയ കീയെ ബന്ധിപ്പിക്കുന്നു. ആധികാരികമാക്കിയ `/account/delete` രണ്ട് റെക്കോർഡുകളും മായ്‌ക്കുന്നു, ബണ്ടിൽ കാലഹരണത്തിന് ശേഷവും ഉടമയ്‌ക്കെതിരെ ആധികാരികമാക്കാൻ കഴിയും. നഷ്ടപ്പെട്ട-ഉടമ-കീ റീസെറ്റ് ഇല്ല.

ഈ റെക്കോർഡുള്ള അക്കൗണ്ടുകൾക്ക്, അപ്‌ലോഡും സന്ദേശ/സീൽ ചെയ്ത പോളും, സീൽ ചെയ്ത ACK-യും മെയിൽബോക്സ് WebSocket തെളിവുകളും നിലനിൽക്കുന്ന ഉടമയെ ഉപയോഗിക്കണം. **`PREKEY_REQUIRE_AUTH=false` അല്ലെങ്കിൽ `QUEUE_REQUIRE_AUTH=false` ആണെങ്കിലും ഒപ്പിടാത്ത അഭ്യർത്ഥനകൾ നിരസിക്കപ്പെടുന്നു.** ആ ഫ്ലാഗുകൾ ഉടമയില്ലാത്ത അക്കൗണ്ടുകൾക്ക് അവയുടെ നിലവിലുള്ള സ്ഥിരസ്ഥിതികളും പാരമ്പര്യ അർത്ഥങ്ങളും നിലനിർത്തുന്നു; ഒപ്പിടാത്ത അപ്‌ലോഡ്/ക്യൂ അഭ്യർത്ഥനകളുടെ വ്യക്തമായ `false` സ്വീകാര്യത ഉള്ളടക്കമില്ലാത്ത ഒരു നിരാകരണ മുന്നറിയിപ്പ് ലോഗ് ചെയ്യുന്നു. മറ്റ് ഓത്ത് ഫ്ലാഗുകൾ മാറ്റമില്ലാതെ തുടരുന്നു. മെയിൽബോക്സ് WebSocket-കൾക്ക് ഇപ്പോഴും എല്ലാവർക്കും ഒപ്പുകൾ ആവശ്യമാണ്.

ക്ലയന്റ്, മടങ്ങിവരുന്ന-അക്കൗണ്ട് ബൂട്ട്, ലീഡർ പ്രമോഷൻ, വീണ്ടും ബന്ധിപ്പിക്കൽ എന്നിവയുൾപ്പെടെ, ക്യൂ പ്രവർത്തനത്തിന് മുമ്പ് ഒപ്പിടൽ ആരംഭത്തിനായി കാത്തിരിക്കുന്നു. പങ്കിട്ട കാത്തിരിപ്പ് അഞ്ച് സെക്കൻഡിൽ പരിമിതപ്പെടുത്തിയിരിക്കുന്നു. പിന്തുണയില്ലാത്ത റൺടൈമുകൾ ഉടൻ തന്നെ ഒപ്പിടാതെ തുടരുന്നു; കുടുങ്ങിയ IDB/കീ-അൺറാപ്പിംഗ് പരിധിക്ക് ശേഷം ഒപ്പിടാതെ തുടരുന്നു, എന്നിട്ട് തയ്യാറാകുമ്പോൾ ഒപ്പിടുന്നു. ഇത് പോൾ ലൂപ്പിനെ സജീവമായി നിലനിർത്തുന്നു, ഒരു ബൈപാസ് **അല്ല**: ഉടമ-പിന്തുണയുള്ള അക്കൗണ്ടുകൾക്ക് അവയുടെ ഒപ്പിടൽ കീ ഉപയോഗയോഗ്യമാകുന്നത് വരെ റിലേയിൽ നിന്ന് സ്വീകരിക്കാൻ കഴിയില്ല. പഴയ സ്റ്റാർട്ടപ്പ് റേസ് ഒഴിവാക്കാൻ Worker-നൊപ്പം അപ്‌ഡേറ്റ് ചെയ്ത ക്ലയന്റ് അസറ്റുകൾ വിന്യസിക്കുക.

അതിന്റെ ഉടമ സംരക്ഷിക്കപ്പെടുന്നതിന് **മുമ്പ്** കാലഹരണപ്പെട്ട ഒരു ബണ്ടിലിൽ നിന്ന് മൈഗ്രേഷന് ഉടമസ്ഥത വീണ്ടെടുക്കാൻ കഴിയില്ല. ആദ്യ രജിസ്ട്രേഷൻ TOFU ആയി തുടരുന്നു. ഉടമസ്ഥത റെക്കോർഡുകൾ നിലവിലുള്ള KV ബാക്കെൻഡ് ഉപയോഗിക്കുന്നു: ഈ മാറ്റത്താൽ ആത്യന്തിക സ്ഥിരതയും ഒരേസമയത്തെ എഴുത്തുകളും രേഖീയമാക്കപ്പെടുന്നില്ല. തെളിവുകൾ നിലവിലുള്ള അഞ്ച് മിനിറ്റ് പുതുമ വിൻഡോയും പ്രവർത്തന/പേലോഡ് ബൈൻഡിംഗും നിലനിർത്തുന്നു; വിൻഡോയ്ക്കുള്ളിലെ സമാനമായ വീണ്ടും ശ്രമങ്ങൾ ഒറ്റത്തവണ നോൺസ് പ്രോട്ടോക്കോൾ അല്ല.

സാന്നിധ്യ എഴുത്തുകൾക്കും TURN ക്രെഡൻഷ്യൽ നൽകലിനും സ്ഥിരമായി ഇതിനകം തന്നെ ഒരു *രജിസ്റ്റർ ചെയ്ത* അക്കൗണ്ട് (പ്രീകീ ബണ്ടിൽ ഉണ്ട്) ആവശ്യമാണ്, എല്ലാ ക്ലയന്റും സ്വയം രജിസ്റ്റർ ചെയ്യുന്നു. സാന്നിധ്യ ഹൃദയമിടിപ്പുകൾ അധികമായി ഒരു Ed25519 ഉടമസ്ഥത തെളിവ് വഹിക്കുന്നു (മിടിപ്പ് അത് സംഭരിക്കുന്ന ഫീൽഡുകളിൽ ഒപ്പിടുന്നു), അത് അവതരിപ്പിക്കുമ്പോഴെല്ലാം Worker അത് പരിശോധിക്കുന്നു — `PRESENCE_SIGN_REQUIRE_AUTH=true` ആ തെളിവ് നിർബന്ധമാക്കുന്നു. ശേഷിക്കുന്ന Ed25519-ഒപ്പ് ഫ്ലാഗുകൾ ഓപ്റ്റ്-ഇൻ ആയി തുടരുന്നു; `wrangler.toml` ഓരോന്നിനെയും എന്തുകൊണ്ടെന്നും രേഖപ്പെടുത്തുന്നു (WebCrypto Ed25519 ഇല്ലാത്ത റൺടൈമുകളിലെ ക്ലയന്റുകൾക്ക് ഒട്ടും ഒപ്പിടാൻ കഴിയില്ല).

പാരമ്പര്യ പ്ലെയിൻ റിലേ (`/api/msg/send`, `/api/msg/poll`) നിരാകരിച്ചിരിക്കുന്നു: അതിന്റെ പ്രതികരണങ്ങൾ ഒരു `Deprecation: true` ഹെഡർ വഹിക്കുന്നു, സീൽ ചെയ്ത പാതയാണ് എല്ലാ നിലവിലെ ക്ലയന്റിനും സ്ഥിര റൂട്ട്. ഒരു തത്സമയ ക്ലയന്റിനും ഇനി ഫാൾബാക്ക് ആവശ്യമില്ലെന്ന് നിങ്ങൾ സ്ഥിരീകരിച്ചുകഴിഞ്ഞാൽ, അത് പൂർണ്ണമായും അപ്രാപ്തമാക്കുക:

```bash
wrangler pages secret put PLAIN_PATH_DISABLED   # set to: true
```

### സൗജന്യ ടയറിനപ്പുറം സ്കെയിലിംഗ്

നിങ്ങൾ സൗജന്യ ടയറിനപ്പുറം വളരുമ്പോൾ ($5/മാസം Workers Paid പ്ലാൻ):

| ഉറവിടം | പണമടച്ച പ്ലാൻ |
|----------|-----------|
| Worker അഭ്യർത്ഥനകൾ | 10 ദശലക്ഷം/മാസം |
| KV എഴുത്തുകൾ | 1 ദശലക്ഷം/മാസം |
| KV സംഭരണം | 1 GB ഉൾപ്പെടുത്തിയിട്ടുണ്ട് |
| CPU സമയം | 30 സെക്കൻഡ്/അഭ്യർത്ഥന |

ഇത് **ആയിരക്കണക്കിന് ഒരേസമയ ഉപയോക്താക്കളെ** പിന്തുണയ്ക്കുന്നു.
