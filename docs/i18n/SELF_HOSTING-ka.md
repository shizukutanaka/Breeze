> **დაწყებამდე: სტანდარტულ დაყენებას სჭირდება Cloudflare ანგარიში.**
> სტანდარტული დაყენება ამ სახელმძღვანელოში — Cloudflare განთავსება
> ქვემოთ — მუშაობს Cloudflare-ზე, ამიტომ დაწყებამდე მზად გქონდეთ Cloudflare ანგარიში.
> თუ არ გსურთ Cloudflare-ის გამოყენება, Docker და
> ჩვეულებრივი Node დაყენებები ამ სახელმძღვანელოში არ საჭიროებს
> Cloudflare ანგარიშს.

Breeze რელეს (relay) გაშვების ორი გზა არსებობს:

1. **საკუთარ სერვერზე განთავსება (Node + Docker)** — რელე თქვენს საკუთარ მანქანაზე ან
   VPS-ზე: ერთი კონტეინერი, ერთი მონაცემთა ტომი, რეგისტრაცია ნაგულისხმევად
   დახურულია. დაიწყეთ აქედან, თუ რელე თქვენთვის და თქვენი ხალხისთვისაა.
2. **Cloudflare** — ოფიციალური ტიპის განლაგება Cloudflare-ის
   უფასო საფეხურზე (რელე, რომელსაც თავად Breeze უშვებს). დაიწყეთ იქიდან, თუ გსურთ
   საჯარო რელე შესანახი სერვერის გარეშე.

ორივე ერთი და იგივე დამმუშავებლის კოდს უშვებს; რელე არის უტყვი,
ურთიერთშემცვლელი საფოსტო ყუთი ორივე შემთხვევაში და ყველა კლიენტი მუშაობს
ყველა რელესთან.

## საკუთარ სერვერზე განთავსება Docker-ით

```bash
# 1. Get the code
git clone https://github.com/shizukutanaka/Breeze.git && cd Breeze

# 2. Start it, with your own Breeze ID admitted (see "Registration"
#    below for how to find it — you can also start closed-to-everyone
#    and add IDs later)
BREEZE_ALLOWLIST=<your Breeze ID> docker compose up -d

# 3. Watch the first-boot log — it prints your relay identity
#    fingerprint; write it down (see "Relay identity")
docker compose logs breeze
```

რელე ემსახურება ჩვეულებრივ HTTP-ს კონტეინერის შიგნით 8787 პორტზე.
**დაასრულეთ TLS შებრუნებულ პროქსიზე (reverse proxy) მის წინ** (Caddy, nginx,
Traefik, Cloudflare Tunnel, …): ბრაუზერები რელეს გამოიყენებენ მხოლოდ
HTTPS/WSS-ით. როდესაც ამას გააკეთებთ, დააყენეთ `TRUST_PROXY: "true"`
`docker-compose.yml`-ში, რათა სიჩქარის შეზღუდვა რეალურ კლიენტის
მისამართზე იყოს დაფუძნებული — და არასოდეს დააყენოთ ის ასეთი პროქსის გარეშე, რადგან სათაური (header),
რომელსაც ის ენდობა, შეიძლება შეიქმნას ნებისმიერის მიერ, ვინც შესასვლელს პირდაპირ მიაღწევს.

გაუშვით ზუსტად **ერთი** კონტეინერი მონაცემთა ტომის წინააღმდეგ: სიჩქარის
შემზღუდველი თითო პროცესისთვის მეხსიერებაშია და თითოეული საფოსტო ყუთის ოპერაციები
თანმიმდევრულია იმ პროცესის შიგნით, ამიტომ მეორე რეპლიკა ვერც ერთს
იმ თვისებებიდან ვერ შეინარჩუნებს. მასშტაბი გაზარდეთ ერთი პროცესისთვის უფრო დიდი მანქანის მიცემით.

### რეგისტრაცია: ნაგულისხმევად დახურული

საკუთარ სერვერზე განთავსებული რელე, რომელზეც ინტერნეტში ნებისმიერს შეეძლება დარეგისტრირება,
ხელახლა შექმნის სპამის/ბოროტად გამოყენების ეკონომიკას, რომლის საკონტროლოდაც ოფიციალური რელეს ლიმიტები
არსებობს, ამიტომ **Docker-ის შეფუთვა დახურული მოდის**: compose
ფაილი გადასცემს `REGISTRATION_ALLOWLIST`-ს (შესაძლოა ცარიელი) და
მხოლოდ მასში არსებულ Breeze ID-ებს შეუძლიათ *ანგარიშების შექმნა* (პირველი prekey
ატვირთვა). რეგისტრაციის დახურვა არასოდეს ეხება იმ ადამიანებს, რომლებიც უკვე სახლობენ
რელეზე — მათი ატვირთვები, დეპოზიტები, შეხვედრები და გამოკითხვები არ არის
შეზღუდული — და რეგისტრაციის გახსნა არის ცალსახა არჩევანი, არასოდეს ნაგულისხმევი.

- **თქვენი Breeze ID** არის 12-სიმბოლოიანი იდენტიფიკატორი თქვენს მოსაწვევ ბმულში
  (მისი `pub` მნიშვნელობის პირველი 12 სიმბოლო). ჰკითხეთ თითოეულ ადამიანს,
  რომელსაც იწვევთ, თავისას იმავე გზით — ID არის საჯარო იდენტიფიკატორი,
  რომელსაც კონტაქტები უკვე ცვლიან, არა საიდუმლო.
- **მიიღეთ ადამიანები** მათი ID-ების ჩამოთვლით: დააყენეთ
  `BREEZE_ALLOWLIST=id1,id2,…` თქვენს shell-ში ან `.env` ფაილში
  `docker-compose.yml`-ის გვერდით, შემდეგ კვლავ `docker compose up -d`.
- **დაიწყეთ ახლა, მიიღეთ მოგვიანებით**: `BREEZE_ALLOWLIST`-ის დაყენების გარეშე, რელე
  მუშაობს ყველასთვის დახურული — გაშვების ჟურნალი ამას ამბობს — და ვერავინ
  დარეგისტრირდება, სანამ ID-ებს არ დაამატებთ.
- **ღია რელე** (ნებისმიერს შეუძლია დარეგისტრირება): მოხსენით კომენტარი
  `REGISTRATION_OPEN: "1"`-დან `docker-compose.yml`-ში. თუ ამას გააკეთებთ, ბოროტად გამოყენების
  ეკონომიკა თქვენია.

### გამოყენების კვოტა: გამორთეთ ის თქვენს რელეზე

Worker-ი მოჰყვება **სამართლიანი გამოყენების კვოტით** ჩართული: თითოეული
საფოსტო ყუთისთვის, მაქსიმუმ 10,000 დეპოზიტი დღეში და 200,000 თვეში (დეპოზიტი არის
ერთი სრული მიწოდების ციკლი — იხილეთ `docs/COST_MODEL.md` §10
პოლიტიკისა და რიცხვებისთვის). ეს ჩარჩო არსებობს *გაზიარებული ნაგულისხმევი რელესთვის*,
რომელიც მუშაობს როგორც უფასო შესასვლელი, რომლის ცვლადი ხარჯები ოპერატორს
სხვაგვარად ყველასთვის ექნებოდა. **რელეზე, რომელსაც უშვებთ
თქვენთვის და თქვენი ხალხისთვის, ჩარჩო უაზროა — გამორთეთ
ის**:

```bash
USAGE_QUOTA_ENABLED=false
```

დააყენეთ ის ყველგან, სადაც თქვენი რელე კითხულობს თავის გარემოს (shell-ი ან
`.env` `docker-compose.yml`-ის გვერდით, Node პროცესის გარემო,
ან Cloudflare Pages-ის საიდუმლოებები). ორი მეზობელი ღილაკი არსებობს, თუ
უშვებთ საზოგადოებრივ რელეს და *გსურთ* ჩარჩო:
`USAGE_QUOTA_DAILY` და `USAGE_QUOTA_MONTHLY` ხელახლა არეგულირებენ ლიმიტებს.
მნიშვნელოვანი შენიშვნები:

- კვოტა ამოქმედდება მხოლოდ მაშინ, როდესაც საფოსტო ყუთები ცხოვრობენ Durable
  Objects-ში (`MAILBOX_BACKEND=do`, ნაგულისხმევი ამ ჰოსტზე); KV
  ბექენდზე ის დოკუმენტირებული არა-მოქმედებაა.
- ლიმიტის მიღმა, გამგზავნები იღებენ ცალსახა `429 USAGE_QUOTA_EXCEEDED`-ს
  (ფანჯრითა და მისი ლიმიტით) ჩუმი გადაგდების ნაცვლად — შეტყობინება
  რჩება გამგზავნის გამავალ ყუთში და მიმღები რჩება
  ხელმისაწვდომი P2P-ით და ნებისმიერი სხვა სახლის რელეთი.

### რელეს იდენტობა

პირველ გაშვებაზე რელე ქმნის მუდმივ Ed25519 იდენტობის გასაღებს
*მონაცემთა ტომის შიგნით* და ბეჭდავს მის ანაბეჭდს (fingerprint) ჟურნალში:

```
relay identity: NEW key generated — fingerprint 3F2A 9C41 …
```

ანაბეჭდი ახდენს *თქვენი* რელეს იდენტიფიცირებას: მიეცით ის თქვენს მომხმარებლებს
გარეგანი არხით (პირადად, სხვა არხით), რათა მათ შეძლონ
მიცემული რელეს, როგორც თქვენ მიერ გაშვებულის, ამოცნობა. იგივე ანაბეჭდი
იბეჭდება ყოველ გაშვებაზე; თუ ის ოდესმე შეიცვლება, მონაცემთა ტომი
შეიცვალა — გამოიძიეთ, სანამ მომხმარებლებს ახლის ნდობას ეტყვით.

კლიენტის აპები ამოწმებენ და ამაგრებენ ამ გასაღებს ავტომატურად (ეტაპი-2 ნაბიჯი 4): პირველ
კონტაქტზე კლიენტი რელეს უწევს გამოწვევას, ხელი მოაწეროს გასაღებით
(`/api/relay/attest`), ინახავს დამოწმებულ გასაღებს ანგარიშთან ერთად და
ხელახლა ამოწმებს ყოველ შემდგომ სესიაზე. ანაბეჭდი, რომელსაც კლიენტი აჩვენებს
(`/security`-ს ქვეშ და პირველი დამაგრებისას toast-ში), მიღებულია
იმავე გასაღებიდან — შეადარეთ ის ზემოთ გაშვების ჟურნალის ხაზს. თუ გასაღები ოდესმე შეიცვლება,
კლიენტის აპები **წყვეტენ რელესთან საუბარს** და აფრთხილებენ
მომხმარებელს; ისინი არასოდეს ამაგრებენ ხელახლა ჩუმად. ანაბეჭდის ცვლილება განიხილეთ როგორც
გამანადგურებელი მოვლენა: აპში არ არის „ახალი გასაღების ნდობის“ ღილაკი
ნაბიჯ 4-ში, ამიტომ ტომის რეალური დაკარგვის შემდეგ თქვენმა მომხმარებლებმა უნდა წაშალონ
აპის შენახული მონაცემები მათი ანგარიშისთვის და ხელახლა დაამაგრონ პირველ კონტაქტზე —
გამოაცხადეთ ახალი ანაბეჭდი გარეგანი არხით ჯერ, თორემ ისინი ვერ გაარჩევენ
თქვენს ახალ გასაღებს თავდამსხმელისგან.

### სარეზერვო ასლი და აღდგენა

სხვა არაფერია სარეზერვოდ.

```bash
# Back up: copy the database out of the (stopped) container
docker compose stop
docker cp "$(docker compose ps -aq breeze)":/data/breeze-relay.db ./breeze-relay-backup.db
docker compose start

# Restore: copy the backup back in as /data/breeze-relay.db before
# starting, and the relay serves identically — same fingerprint.
docker compose stop
docker cp ./breeze-relay-backup.db "$(docker compose ps -aq breeze)":/data/breeze-relay.db
docker compose start
```

#### TURN სერვერი (შემზღუდველი ქსელებისთვის)

TURN არის ის, თუ როგორ კვეთენ ზარები და მხოლოდ-რელეს (IP-ის დამალვის) კავშირები
შემზღუდველ NAT-ებს. რომელ TURN-ს გასცემს თქვენი რელე, არის **თქვენი** არჩევანი
როგორც ოპერატორის — Worker-ი ცდის, თანმიმდევრობით:

```bash
# Option A: Cloudflare Calls ($0.05/GB, global anycast)
wrangler pages secret put TURN_KEY_ID
wrangler pages secret put TURN_KEY_API_TOKEN

# Option B: your own coturn (HMAC time-limited credentials — the Worker
# mints a 24h username/credential per registered user from the secret)
#   coturn: use-auth-secret, static-auth-secret=<same secret>
wrangler pages secret put TURN_URL      # turn:your-server:3478
wrangler pages secret put TURN_SECRET

# Option C: static credentials (metered.ca, Twilio, …)
wrangler pages secret put TURN_URL
wrangler pages secret put TURN_USERNAME
wrangler pages secret put TURN_CREDENTIAL

# Option D: No config → free Open Relay (20GB/month). This is a third
# party's PUBLIC quota, shared with every unconfigured relay — fine for
# a first run, not a foundation. Opt out explicitly and callers get
# STUN only (some restrictive-NAT calls will then fail, visibly):
wrangler pages secret put TURN_OPENRELAY_FALLBACK   # set to: false
```

**გადაამოწმეთ, რა დააკონფიგურირეთ სინამდვილეში:** `GET /api/health` იტყობინება
ეფექტურ რეჟიმს როგორც `turnProvider` (`cloudflare` | `custom` | `static` |
`openrelay` | `none`). ძველი `turn` boolean ასახავს მხოლოდ
`TURN_URL`-ს, ამიტომ ის კითხულობს `false`-ს რეკომენდებული ვარიანტი A-სთვის — გამოიყენეთ
`turnProvider`. კლიენტის აპები აჩვენებენ იმავე პროვაიდერს `/security`-ში, ამიტომ
Open Relay-ის სათადარიგოზე მყოფ მომხმარებელს შეუძლია დაინახოს, რომ მესამე მხარე არელეებს მის
ზარის მედიას (მხოლოდ მეტამონაცემები — თავად მედია დაშიფრულია DTLS-SRTP-ით).
