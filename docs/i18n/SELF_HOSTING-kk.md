> **Бастамас бұрын: стандартты орналастыруға Cloudflare тіркелгісі қажет.**
> Бұл нұсқаулықтағы стандартты орналастыру — төмендегі Cloudflare
> орналастыруы — Cloudflare-да жұмыс істейді, сондықтан бастамас бұрын
> Cloudflare тіркелгісін дайындап қойыңыз. Cloudflare-ды қолданғыңыз
> келмесе, бұл нұсқаулықтағы Docker және жалаң Node орналастыруларына
> Cloudflare тіркелгісі қажет емес.

Breeze ретрансляторын іске қосудың екі тәсілі бар:

1. **Өз серверінде (Node + Docker)** — ретранслятор өз машинаңызда немесе
   VPS-те: бір контейнер, бір деректер көлемі, тіркелу бастапқыда
   жабық. Ретранслятор сізге және сіздің адамдарыңызға арналған болса,
   осыдан бастаңыз.
2. **Cloudflare** — Cloudflare-дың тегін жоспарындағы ресми үлгідегі
   орналастыру (Breeze-дің өзі іске қосатын ретранслятор). Қызмет
   көрсететін сервері жоқ қоғамдық ретранслятор қаласаңыз, содан бастаңыз.

Екеуі де бірдей өңдеуші кодты іске қосады; ретранслятор екі жағдайда да
қарапайым, ауыстырылатын пошта жәшігі, және әр клиент әр ретранслятормен
жұмыс істейді.

## Docker арқылы өз серверінде

```bash
# 1. Get the code
git clone https://github.com/shizukutanaka/Breeze.git && cd Breeze

# 2. Start it, with your own Breeze ID admitted (see "Registration"
#    below for how to find it — you can also start closed-to-everyone
#    and add IDs later)
BREEZE_ALLOWLIST=<your Breeze ID> docker compose up -d

# 3. Watch the first-boot log — it prints your relay identity
#    fingerprint; write it down (see "Relay identity")
docker compose logs breeze
```

Ретранслятор контейнер ішінде 8787 портында қарапайым HTTP қызметін көрсетеді.
**Оның алдына кері прокси қойып, TLS-ті сонда аяқтаңыз** (Caddy, nginx,
Traefik, Cloudflare Tunnel, …): браузерлер ретрансляторды тек
HTTPS/WSS арқылы қолданады. Олай жасағанда, жылдамдық шегі нақты клиент
мекенжайы бойынша кілттенуі үшін `docker-compose.yml` файлында
`TRUST_PROXY: "true"` деп белгілеңіз — және мұндай прокси болмаса оны ешқашан
белгілемеңіз, өйткені ол сенетін тақырыпты кіру нүктесіне тікелей жете алатын
кез келген адам қолдан жасай алады.

Деректер көлеміне қарсы дәл **бір** контейнер іске қосыңыз: жылдамдық
шектеушісі әр үдеріс үшін жадта тұрады және әр пошта жәшігінің операциялары
сол үдерістің ішінде реттеледі, сондықтан екінші көшірмеде бұл қасиеттердің
ешқайсысы болмас еді. Ауқымды бір үдеріске үлкенірек машина беру арқылы
ұлғайтыңыз.

### Тіркелу: бастапқыда жабық

Интернеттен кез келген адам тіркеле алатын өз серверлік ретранслятор
ресми ретранслятордың шектеулері басқару үшін бар спам/теріс пайдалану
экономикасын қайта жасар еді, сондықтан **Docker қаптамасы жабық күйінде
жеткізіледі**: compose файлы `REGISTRATION_ALLOWLIST` (бос болуы да мүмкін)
өткізеді және тек сондағы Breeze ID-лері ғана *тіркелгі жасай* алады (алғашқы
prekey жүктеуі). Тіркелуді жабу ретрансляторда бұрыннан үйі бар адамдарға
ешқашан әсер етпейді — олардың жүктеулері, салымдары, кездесулері мен
сұраулары қақпаланбайды — және тіркелуді ашу ашық таңдау, ешқашан әдепкі емес.

- **Сіздің Breeze ID-іңіз** — шақыру сілтемеңіздегі 12 таңбалы идентификатор
  (оның `pub` мәнінің алғашқы 12 таңбасы). Шақырған әр адамнан өздерінікін
  дәл солай сұраңыз — ID контакттар онсыз да алмасатын қоғамдық
  идентификатор, құпия емес.
- **Адамдарды қабылдау** үшін олардың ID-лерін тізімдеңіз: қабығыңызда немесе
  `docker-compose.yml` жанындағы `.env` файлында
  `BREEZE_ALLOWLIST=id1,id2,…` деп белгілеп, содан кейін қайта
  `docker compose up -d` орындаңыз.
- **Қазір бастап, кейін қабылдаңыз**: `BREEZE_ALLOWLIST` белгіленбесе,
  ретранслятор барлығына жабық жұмыс істейді — іске қосу журналы солай дейді —
  және сіз ID-лер қосқанша ешкім тіркеле алмайды.
- **Ашық ретранслятор** (кез келген адам тіркеле алады): `docker-compose.yml`
  файлындағы `REGISTRATION_OPEN: "1"` жолының түсініктемесін алып тастаңыз.
  Олай жасасаңыз, теріс пайдалану экономикасы сіздікі болады.

### Қолдану квотасы: өз ретрансляторыңызда өшіріңіз

Жұмысшы **әділ қолдану квотасы** іске қосылған күйінде жеткізіледі: әр пошта
жәшігі үшін күніне ең көбі 10 000 салым және айына 200 000 (салым — бір толық
жеткізу циклі — саясат пен сандар үшін `docs/COST_MODEL.md` §10 қараңыз).
Бұл шеңбер оператор әйтпесе барлығы үшін көтеретін ауыспалы шығындары бар
тегін кіру орны ретінде іске қосылатын *ортақ әдепкі ретранслятор* үшін бар.
**Өзіңізге және адамдарыңызға арнап іске қосатын ретрансляторда шеңбердің
мәні жоқ — оны өшіріңіз**:

```bash
USAGE_QUOTA_ENABLED=false
```

Оны ретрансляторыңыз ортасын оқитын жерде белгілеңіз (қабық немесе
`docker-compose.yml` жанындағы `.env`, Node үдерісінің ортасы
немесе Cloudflare Pages құпиялары). Қауымдастық ретрансляторын іске
қосып, шеңберді *қаласаңыз*, екі көрші тетік бар:
`USAGE_QUOTA_DAILY` және `USAGE_QUOTA_MONTHLY` шектерді қайта баптайды.
Маңызды ескертпелер:

- Квота тек пошта жәшіктері Durable Objects-те тұрғанда ғана қолданылады
  (`MAILBOX_BACKEND=do`, бұл хосттағы әдепкі); KV артқы жағында ол
  құжатталған әрекетсіз операция.
- Шектен асқанда, жіберушілер үнсіз тастаудың орнына ашық
  `429 USAGE_QUOTA_EXCEEDED` алады (терезесі мен шегімен бірге) — хабарлама
  жіберушінің шығыс жәшігінде қалады, алушы P2P арқылы және кез келген басқа
  үй ретрансляторы арқылы қолжетімді болып қалады.

### Ретранслятордың жеке басы

Алғашқы іске қосуда ретранслятор *деректер көлемінің ішінде* тұрақты Ed25519
жеке бас кілтін жасайды және оның саусақ ізін журналда басып шығарады:

```
relay identity: NEW key generated — fingerprint 3F2A 9C41 …
```

Саусақ ізі *сіздің* ретрансляторыңызды анықтайды: оны қолданушыларыңызға
арнадан тыс (жеке өзіңіз, басқа арна арқылы) беріңіз, сонда олар өздеріне
берілген ретрансляторды сіз іске қосатын ретранслятор ретінде тани алады.
Сол саусақ ізі әр іске қосуда басылады; ол қашан болса да өзгерсе, деректер
көлемі ауыстырылған — қолданушыларға жаңасына сену керектігін айтпас бұрын
тексеріңіз.

Клиенттер бұл кілтті автоматты түрде тексеріп, бекітеді (2-кезең, 4-қадам):
алғашқы байланыста клиент ретрансляторға кілтпен қол қоюға шақыру жібереді
(`/api/relay/attest`), тексерілген кілтті тіркелгімен бірге сақтайды және
кейінгі әр сессияда қайта тексереді. Клиент көрсететін саусақ ізі
(`/security` астында және алғашқы бекітудегі хабарландыруда) сол кілттен
шығарылады — оны жоғарыдағы іске қосу журналы жолымен салыстырыңыз. Кілт
қашан болса да өзгерсе, клиенттер **ретранслятормен сөйлесуді тоқтатады**
және қолданушыны ескертеді; олар ешқашан үнсіз қайта бекітпейді. Саусақ ізінің
өзгеруін бұзатын оқиға ретінде қарастырыңыз: 4-қадамда қолданба ішінде
«жаңа кілтке сену» батырмасы жоқ, сондықтан көлемнің шынайы жоғалуынан кейін
қолданушыларыңыз тіркелгілері үшін қолданбаның сақталған деректерін тазалап,
алғашқы байланыста қайта бекітуі керек — алдымен жаңа саусақ ізін арнадан
тыс хабарлаңыз, әйтпесе олар сіздің жаңа кілтіңізді шабуылдаушының кілтінен
ажырата алмайды.

### Сақтық көшірме және қалпына келтіру

**Деректер көлемі — ретранслятор күйінің барлығы**: каталогты, пошта
жәшіктерін және ретранслятордың жеке бас кілтін ұстайтын бір SQLite файлы.
Сақтық көшірмесін жасайтын басқа ештеңе жоқ.

```bash
# Back up: copy the database out of the (stopped) container
docker compose stop
docker cp "$(docker compose ps -aq breeze)":/data/breeze-relay.db ./breeze-relay-backup.db
docker compose start

# Restore: copy the backup back in as /data/breeze-relay.db before
# starting, and the relay serves identically — same fingerprint.
docker compose stop
docker cp ./breeze-relay-backup.db "$(docker compose ps -aq breeze)":/data/breeze-relay.db
docker compose start
```

### Жаңарту

```bash
git pull origin main
docker compose up -d --build
```

Күй образда емес, көлемде тұрады, сондықтан жаңарту қолданушыларыңыздың
деректеріне ешқашан тиіспейді.

## Жалаң Node арқылы өз серверінде (Docker-сіз)

```bash
node server/index.js   # Node ≥ 24, no npm dependencies to install
```

Конфигурация — тек орта айнымалылары — `server/README.md`
барлығын тізімдейді. Docker жолынан екі айырмашылық:

- **Деректер файлы** әдепкі бойынша `./breeze-relay.db` (`BREEZE_DB_PATH`
  арқылы өзгертіңіз); бұл ретранслятордың жеке басын қоса алғанда, сол бір
  файлдық күй. Оның сақтық көшірмесін де солай жасаңыз: тоқтатыңыз,
  көшіріңіз, қайта іске қосыңыз.
- **Тіркелу сіз жапқанша ашық**: жабық әдепкі — Docker қаптамасының
  қасиеті. Жалаң кіруді жабу үшін `REGISTRATION_ALLOWLIST=id1,id2`
  (немесе барлығына жабық үшін бос мән) белгілеңіз; `REGISTRATION_OPEN=1`
  ашық түрде қайта ашады.

## Cloudflare орналастыруы

### Ең аз орналастыру (айына 0 доллар, 5 минут)

```bash
# 1. Install Wrangler CLI
npm install -g wrangler

# 2. Login to Cloudflare
wrangler login

# 3. Deploy
wrangler pages deploy . --project-name=breeze

# 4. Create a KV namespace and declare it in wrangler.toml
wrangler kv:namespace create KV
# Copy the new namespace's ID and put it in wrangler.toml, replacing the
# id in the [[kv_namespaces]] section (binding = "KV"). Pages takes its
# bindings from wrangler.toml; a binding set only in the Dashboard is
# NOT applied while a wrangler.toml exists.
# Then deploy again so the binding takes effect:
wrangler pages deploy . --project-name=breeze

# 5. Visit your deployment's URL (https://<your-project>.pages.dev)
```

**Осы ғана.** Push хабарландыруларынан басқа барлық функциялар жұмыс істейді.
Cloudflare орналастыруында тіркелу өзіңіз `REGISTRATION_ALLOWLIST`
белгілемесеңіз **ашық** екенін ескеріңіз (`.env.example` қараңыз);
бастапқыда жабық қаптама — жоғарыдағы Docker жолы.

### 0 долларға не жұмыс істейді

| Функция | Күй | Ескертпелер |
|---------|--------|-------|
| E2E шифрланған чат | ✓ | Толық Double Ratchet |
| P2P хабар алмасу | ✓ | WebRTC DataChannel |
| Дауыстық/бейне қоңыраулар | ✓ | WebRTC + тегін STUN |
| TURN ретрансляторы | ✓ | Open Relay (айына 20GB тегін) |
| Топтар (1,000 мүше) | ✓ | Sender Key O(1) |
| Файл тасымалдау | ✓ | P2P арқылы 50MB-қа дейін |
| 51 тіл | ✓ | Ағылшын тілі кірістірілген + 50 толық тіл файлы, автоматты түрде анықталады |
| Офлайн/PWA | ✓ | Service Worker |
| Push хабарландырулары | ✗ | VAPID кілттері қажет |

Көп тіркелгілік төлем (Lite/Plus/Pro) қолжетімді емес —
[SECURITY.md](../../SECURITY.md) құжатының «Removed: multi-account billing» бөлімін қараңыз. Әр тіркелгі
жоспар қақпасынсыз тегін шексіз жергілікті қосалқы тіркелгілер алады.

### Тегін жоспар шектеулері

| Ресурс | Тегін жоспар | Белсенді қолданушыға шаққандағы қолдану |
|----------|-----------|----------------------|
| Worker сұраулары | Күніне 100 000 | ~Күніне 500 (сұрау + сигнал) |
| KV оқулары | Күніне 100 000 | ~Күніне 200 |
| KV жазулары | Күніне 1 000 | ~Күніне 350 (оңтайландырылған) |
| KV сақтауы | 1 GB | ~Қолданушыға 10 KB |
| Статикалық активтер | Шексіз | ~894 KB (бір HTML) |

**Тегін жоспарда ~3 бір мезгілде белсенді қолданушыны қолдайды.**

### Қосымша функцияларды қосу

#### Push хабарландырулары (тегін)

```bash
# Generate VAPID keys
npx web-push generate-vapid-keys

# Set secrets
wrangler pages secret put VAPID_PUBLIC_KEY
wrangler pages secret put VAPID_PRIVATE_KEY
```

#### TURN сервері (шектеулі желілер үшін)

TURN — қоңыраулар мен тек ретрансляторлық (IP жасыратын) қосылымдардың
шектеулі NAT-тарды кесіп өту тәсілі. Ретрансляторыңыз қай TURN-ды беретіні
оператор ретінде **сіздің** таңдауыңыз — Worker рет-ретімен мыналарды
сынап көреді:

```bash
# Option A: Cloudflare Calls ($0.05/GB, global anycast)
wrangler pages secret put TURN_KEY_ID
wrangler pages secret put TURN_KEY_API_TOKEN

# Option B: your own coturn (HMAC time-limited credentials — the Worker
# mints a 24h username/credential per registered user from the secret)
#   coturn: use-auth-secret, static-auth-secret=<same secret>
wrangler pages secret put TURN_URL      # turn:your-server:3478
wrangler pages secret put TURN_SECRET

# Option C: static credentials (metered.ca, Twilio, …)
wrangler pages secret put TURN_URL
wrangler pages secret put TURN_USERNAME
wrangler pages secret put TURN_CREDENTIAL

# Option D: No config → free Open Relay (20GB/month). This is a third
# party's PUBLIC quota, shared with every unconfigured relay — fine for
# a first run, not a foundation. Opt out explicitly and callers get
# STUN only (some restrictive-NAT calls will then fail, visibly):
wrangler pages secret put TURN_OPENRELAY_FALLBACK   # set to: false
```

**Шын мәнінде не баптағаныңызды тексеріңіз:** `GET /api/health` тиімді
режимді `turnProvider` ретінде хабарлайды (`cloudflare` | `custom` | `static` |
`openrelay` | `none`). Ескі `turn` логикалық мәні тек
`TURN_URL`-ді көрсетеді, сондықтан ұсынылатын A нұсқасы үшін ол `false`
болып оқылады — `turnProvider`-ді қолданыңыз. Клиенттер сол провайдерді
`/security` бөлімінде көрсетеді, сондықтан Open Relay қосалқысындағы
қолданушы үшінші тараптың оның қоңырау медиасын ретрансляциялайтынын көре
алады (тек метадеректер — медианың өзі DTLS-SRTP арқылы шифрланған).

#### Аутентификацияны күшейту және қарапайым ретранслятор жолы

Prekey жүктеулері енді қол қою иелігін `prekey-owner:<userId>` мекенінде
**TTL-сіз** бөлек сақтайды. Бар топтама иелігі келесі жүктеуде, ауыстыру
қабылданбас бұрын, жалқау түрде көшіріледі. Жаңа Ed25519 топтамалары да
сол жазбаны орнатады. Мерзімі өткен prekey топтамаларын тазалағанда бұл
жазбаларды сақтаңыз: топтама мерзімінің өтуін күту жаңа иеге рұқсат
бермеуі керек. Айналым алдыңғы ие қол қойған жүктеуді талап етеді, жаңа
кілтті бар жүктеу дайджестінде байланыстырады. Аутентификацияланған
`/account/delete` екі жазбаны да өшіреді және топтама мерзімі өткеннен
кейін де иеге қарсы аутентификация жасай алады. Жоғалған ие кілтін
қалпына келтіру жоқ.

Бұл жазбасы бар тіркелгілер үшін жүктеу және хабарлама/мөрленген сұрау,
мөрленген ACK және пошта жәшігі WebSocket дәлелдері тұрақты иені қолдануы
керек. **Қол қойылмаған сұраулар `PREKEY_REQUIRE_AUTH=false` немесе
`QUEUE_REQUIRE_AUTH=false` болса да қабылданбайды.**
Бұл жалаулар иесі жоқ тіркелгілер үшін бар әдепкі мәндері мен ескі
семантикасын сақтайды; қол қойылмаған жүктеу/кезек сұрауларын ашық `false`
қабылдау мазмұнсыз ескірту ескертуін жазады. Басқа аутентификация
жалаулар өзгеріссіз. Пошта жәшігі WebSocket-тары бәрібір барлығы үшін
қолтаңба талап етеді.

Клиент кезек әрекетінен бұрын қол қоюдың басталуын күтеді, оған қайтып
келген тіркелгінің жүктелуі, көшбасшыға көтерілу және қайта қосылу кіреді.
Ортақ күту бес секундпен шектелген. Қолдау көрсетілмейтін жұмыс орталары
бірден қол қойылмаған күйінде жалғастырады; тұрып қалған IDB/кілтті ашу
шектен кейін қол қойылмаған күйінде жалғастырып, дайын болғанда қол қояды.
Бұл сұрау циклін тірі ұстайды, **айналып өту емес**: иесі бар тіркелгілер
қол қою кілті қолданыла алатын болғанша ретранслятордан ала алмайды. Ескі
іске қосу жарысын болдырмау үшін жаңартылған клиент активтерін Worker-мен
бірге орналастырыңыз.

Көшіру иелікті иесі сақталмай тұрып **бұрын** мерзімі өткен топтамадан
қалпына келтіре алмайды. Алғашқы тіркелу TOFU болып қалады. Иелік жазбалары
бар KV артқы жағын қолданады: бір мезгілдегі жазулар мен ақырғы сәйкестік
бұл өзгеріспен сызықты етілмейді. Дәлелдер бар бес минуттық балғындық
терезесін және операция/жүктеме байланыстыруын сақтайды; терезе ішіндегі
бірдей қайталаулар бір реттік nonce хаттамасы емес.

Қатысу жазулары мен TURN тіркелгі деректерін беру бастапқыда *тіркелген*
тіркелгіні (prekey топтамасы бар) талап етеді және әр клиент автоматты
түрде тіркеледі. Қатысу жүрек соғыстары қосымша Ed25519 иелік дәлелін
тасиды (соғыс сақтайтын өрістеріне қол қояды), Worker ол ұсынылған кезде
әрқашан тексереді — `PRESENCE_SIGN_REQUIRE_AUTH=true` сол дәлелді міндетті
етеді. Қалған Ed25519 қолтаңба жалаулары таңдамалы болып қалады;
`wrangler.toml` әрқайсысын және себебін құжаттайды (WebCrypto Ed25519-і
жоқ жұмыс орталарындағы клиенттер мүлдем қол қоя алмайды).

Ескі қарапайым ретранслятор (`/api/msg/send`, `/api/msg/poll`) ескірген:
оның жауаптары `Deprecation: true` тақырыбын тасиды, мөрленген жол әр
қазіргі клиент үшін әдепкі маршрут. Ешқандай тірі клиентке қосалқы жол
қажет емес екенін растағаннан кейін оны толықтай өшіріңіз:

```bash
wrangler pages secret put PLAIN_PATH_DISABLED   # set to: true
```
