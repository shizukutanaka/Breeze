Есть два способа запустить ретранслятор Breeze:

1. **Самостоятельное размещение (Node + Docker)** — ретранслятор на
   вашей собственной машине или VPS: один контейнер, один том данных,
   регистрация закрыта по умолчанию. Начните здесь, если ретранслятор
   для вас и ваших людей.
2. **Cloudflare** — развёртывание в официальном стиле на бесплатном
   тарифе Cloudflare (ретранслятор, который запускает сам Breeze).
   Начните там, если хотите публичный ретранслятор без сервера,
   который нужно обслуживать.

Оба запускают идентичный код обработчика; ретранслятор в любом случае
является глупым, взаимозаменяемым почтовым ящиком, и каждый клиент
работает с каждым ретранслятором.

## Самостоятельное размещение с Docker

```bash
# 1. Get the code
git clone https://github.com/shizukutanaka/Breeze.git && cd Breeze

# 2. Start it, with your own Breeze ID admitted (see "Registration"
#    below for how to find it — you can also start closed-to-everyone
#    and add IDs later)
BREEZE_ALLOWLIST=<your Breeze ID> docker compose up -d

# 3. Watch the first-boot log — it prints your relay identity
#    fingerprint; write it down (see "Relay identity")
docker compose logs breeze
```

Ретранслятор обслуживает обычный HTTP на порту 8787 внутри
контейнера. **Завершайте TLS на обратном прокси перед ним** (Caddy,
nginx, Traefik, Cloudflare Tunnel, …): браузеры будут использовать
ретранслятор только по HTTPS/WSS. Когда сделаете это, установите
`TRUST_PROXY: "true"` в `docker-compose.yml`, чтобы ограничение
частоты опиралось на реальный адрес клиента, — и никогда не
устанавливайте это без такого прокси, потому что заголовок, которому
он доверяет, может подделать любой, кто может напрямую достичь входа.

Запускайте ровно **один** контейнер на том данных: ограничитель
частоты находится в памяти на процесс, а операции каждого почтового
ящика сериализуются внутри этого процесса, поэтому вторая реплика не
сохранила бы ни одного из этих свойств. Масштабируйтесь, давая одному
процессу машину побольше.

### Регистрация: закрыта по умолчанию

Самостоятельно размещённый ретранслятор, на котором мог бы
зарегистрироваться любой в интернете, воссоздал бы экономику
спама/злоупотреблений, для контроля которой существуют ограничения
официального ретранслятора, поэтому **пакет Docker поставляется
закрытым**: файл compose передаёт `REGISTRATION_ALLOWLIST` (возможно,
пустой), и только ID Breeze из него могут *создавать аккаунты* (первая
загрузка prekey). Закрытие регистрации никогда не затрагивает людей,
уже обосновавшихся на ретрансляторе, — их загрузки, депозиты,
rendezvous и опросы не ограничиваются, — а открытие регистрации
является явным выбором, никогда не значением по умолчанию.

- **Ваш ID Breeze** — это 12-символьный идентификатор в вашей ссылке
  приглашения (первые 12 символов её значения `pub`). Спросите у
  каждого приглашаемого его ID таким же образом — ID является
  публичным идентификатором, которым контакты уже обмениваются, а не
  секретом.
- **Допускайте людей**, перечисляя их ID: установите
  `BREEZE_ALLOWLIST=id1,id2,…` в вашей оболочке или в файле `.env`
  рядом с `docker-compose.yml`, затем снова `docker compose up -d`.
- **Начните сейчас, допускайте позже**: без установленного
  `BREEZE_ALLOWLIST` ретранслятор работает закрытым для всех — журнал
  загрузки говорит об этом — и никто не может зарегистрироваться, пока
  вы не добавите ID.
- **Открытый ретранслятор** (зарегистрироваться может любой):
  раскомментируйте `REGISTRATION_OPEN: "1"` в `docker-compose.yml`.
  Если сделаете это, экономика злоупотреблений — ваша.

### Квота использования: отключите её на своём ретрансляторе

Worker поставляется с включённой **квотой добросовестного
использования**: на почтовый ящик — не более 10 000 депозитов в день
и 200 000 в месяц (депозит — это один полный цикл доставки; см.
`docs/COST_MODEL.md` §10 о политике и числах). Эта рамка существует
для *общего ретранслятора по умолчанию*, который работает как
бесплатный вход, переменные издержки которого оператору иначе
пришлось бы нести за всех. **На ретрансляторе, который вы запускаете
для себя и своих людей, рамка бессмысленна — отключите её**:

```bash
USAGE_QUOTA_ENABLED=false
```

Установите это там, где ваш ретранслятор читает своё окружение
(оболочка или `.env` рядом с `docker-compose.yml`, окружение процесса
Node или секреты Cloudflare Pages). Существуют два соседних регулятора,
если вы запускаете общественный ретранслятор и *хотите* рамку:
`USAGE_QUOTA_DAILY` и `USAGE_QUOTA_MONTHLY` перенастраивают пределы.
Заметки, которые имеют значение:

- Квота применяется, только когда почтовые ящики живут в Durable
  Objects (`MAILBOX_BACKEND=do`, значение по умолчанию на этом хосте);
  на бэкенде KV она является задокументированным no-op.
- За пределом отправители получают явный `429 USAGE_QUOTA_EXCEEDED`
  (с окном и его пределом) вместо молчаливого сброса — сообщение
  остаётся в исходящих отправителя, а получатель остаётся достижимым
  по P2P и через любой другой домашний ретранслятор.

### Идентичность ретранслятора

При первой загрузке ретранслятор генерирует постоянный ключ
идентичности Ed25519 *внутри тома данных* и печатает его отпечаток в
журнале:

```
relay identity: NEW key generated — fingerprint 3F2A 9C41 …
```

Отпечаток идентифицирует *ваш* ретранслятор: передайте его вашим
пользователям по внешнему каналу (лично, по другому каналу), чтобы
они могли узнать ретранслятор, который им передали, как тот, который
запускаете вы. Тот же отпечаток печатается при каждой загрузке; если
он когда-либо изменится, том данных был заменён — расследуйте, прежде
чем говорить пользователям доверять новому.

Клиенты проверяют и закрепляют этот ключ автоматически (этап 2, шаг
4): при первом контакте клиент предлагает ретранслятору подписать
ключом (`/api/relay/attest`), сохраняет проверенный ключ вместе с
аккаунтом и повторно проверяет его на каждой последующей сессии.
Отпечаток, который показывает клиент (в `/security` и во всплывающем
сообщении при первом закреплении), выводится из того же ключа —
сравните его со строкой журнала загрузки выше. Если ключ когда-либо
изменится, клиенты **перестанут разговаривать с ретранслятором** и
предупредят пользователя; они никогда не перезакрепляют молча.
Относитесь к изменению отпечатка как к ломающему событию: в шаге 4
нет внутриприложенческой кнопки «доверять новому ключу», поэтому после
подлинной потери тома вашим пользователям придётся очистить сохранённые
данные приложения для их аккаунта и переприкрепиться при первом
контакте — объявите новый отпечаток по внешнему каналу заранее, иначе
они не смогут отличить ваш новый ключ от ключа атакующего.

### Резервное копирование и восстановление

**Том данных — это всё состояние ретранслятора**: один файл SQLite,
содержащий каталог, почтовые ящики и ключ идентичности ретранслятора.
Больше нечего резервировать.

```bash
# Back up: copy the database out of the (stopped) container
docker compose stop
docker cp "$(docker compose ps -aq breeze)":/data/breeze-relay.db ./breeze-relay-backup.db
docker compose start

# Restore: copy the backup back in as /data/breeze-relay.db before
# starting, and the relay serves identically — same fingerprint.
docker compose stop
docker cp ./breeze-relay-backup.db "$(docker compose ps -aq breeze)":/data/breeze-relay.db
docker compose start
```

### Обновление

```bash
git pull origin main
docker compose up -d --build
```

Состояние живёт в томе, а не в образе, поэтому обновление никогда не
затрагивает данные ваших пользователей.

## Самостоятельное размещение с голым Node (без Docker)

```bash
node server/index.js   # Node ≥ 24, no npm dependencies to install
```

Конфигурация — только переменные окружения — `server/README.md`
перечисляет их все. Два отличия от пути Docker:

- **Файл данных** по умолчанию — `./breeze-relay.db` (переопределяется
  через `BREEZE_DB_PATH`); это то же состояние в одном файле, включая
  идентичность ретранслятора. Резервируйте его так же: остановите,
  скопируйте, перезапустите.
- **Регистрация открыта, если вы её не закроете**: закрытое значение
  по умолчанию — свойство пакета Docker. Чтобы закрыть голый вход,
  установите `REGISTRATION_ALLOWLIST=id1,id2` (или пустое значение для
  закрытого для всех); `REGISTRATION_OPEN=1` явно открывает снова.

## Развёртывание на Cloudflare

### Минимальное развёртывание ($0/месяц, 5 минут)

```bash
# 1. Install Wrangler CLI
npm install -g wrangler

# 2. Login to Cloudflare
wrangler login

# 3. Deploy
wrangler pages deploy . --project-name=breeze

# 4. Create a KV namespace and declare it in wrangler.toml
wrangler kv:namespace create KV
# Copy the new namespace's ID and put it in wrangler.toml, replacing the
# id in the [[kv_namespaces]] section (binding = "KV"). Pages takes its
# bindings from wrangler.toml; a binding set only in the Dashboard is
# NOT applied while a wrangler.toml exists.
# Then deploy again so the binding takes effect:
wrangler pages deploy . --project-name=breeze

# 5. Visit your deployment's URL (https://<your-project>.pages.dev)
```

**Вот и всё.** Все функции работают, кроме push-уведомлений. Обратите
внимание, что регистрация при развёртывании на Cloudflare **открыта**,
если вы сами не установите `REGISTRATION_ALLOWLIST` (см.
`.env.example`); пакет, закрытый по умолчанию, — это путь Docker выше.

### Добавление необязательных функций

#### Push-уведомления (бесплатно)

```bash
# Generate VAPID keys
npx web-push generate-vapid-keys

# Set secrets
wrangler pages secret put VAPID_PUBLIC_KEY
wrangler pages secret put VAPID_PRIVATE_KEY
```

#### Сервер TURN (для ограничительных сетей)

TURN — это то, как звонки и соединения только через ретранслятор
(скрытие IP) пересекают ограничительные NAT. Какой TURN раздаёт ваш
ретранслятор — это **ваш** выбор как оператора: Worker пробует в
следующем порядке:

```bash
# Option A: Cloudflare Calls ($0.05/GB, global anycast)
wrangler pages secret put TURN_KEY_ID
wrangler pages secret put TURN_KEY_API_TOKEN

# Option B: your own coturn (HMAC time-limited credentials — the Worker
# mints a 24h username/credential per registered user from the secret)
#   coturn: use-auth-secret, static-auth-secret=<same secret>
wrangler pages secret put TURN_URL      # turn:your-server:3478
wrangler pages secret put TURN_SECRET

# Option C: static credentials (metered.ca, Twilio, …)
wrangler pages secret put TURN_URL
wrangler pages secret put TURN_USERNAME
wrangler pages secret put TURN_CREDENTIAL

# Option D: No config → free Open Relay (20GB/month). This is a third
# party's PUBLIC quota, shared with every unconfigured relay — fine for
# a first run, not a foundation. Opt out explicitly and callers get
# STUN only (some restrictive-NAT calls will then fail, visibly):
wrangler pages secret put TURN_OPENRELAY_FALLBACK   # set to: false
```

**Проверьте, что вы на самом деле настроили:** `GET /api/health`
сообщает эффективный режим как `turnProvider` (`cloudflare` |
`custom` | `static` | `openrelay` | `none`). Старый булев `turn`
отражает только `TURN_URL`, поэтому для рекомендуемого варианта A он
читается как `false` — используйте `turnProvider`. Клиенты показывают
того же провайдера в `/security`, поэтому пользователь на запасном
Open Relay может видеть, что третья сторона ретранслирует медиа его
звонков (только метаданные — само медиа зашифровано DTLS-SRTP).

#### Усиление аутентификации и путь простого ретранслятора

Загрузки prekey теперь сохраняют владение подписью отдельно в
`prekey-owner:<userId>` **без TTL**. Существующее владение бандлами
мигрирует лениво при следующей загрузке, прежде чем будет принята
замена. Новые бандлы Ed25519 также устанавливают эту запись. Сохраняйте
эти записи при чистке истёкших бандлов prekey: ожидание истечения
бандла не должно позволять нового владельца. Ротация требует загрузки,
подписанной предыдущим владельцем, связывая новый ключ в существующем
дайджесте загрузки. Аутентифицированное `/account/delete` стирает обе
записи и может аутентифицироваться против владельца даже после
истечения бандла. Сброса при потере ключа владельца не существует.

Для аккаунтов с этой записью загрузки и опросы сообщений/sealed,
sealed ACK и доказательства WebSocket почтового ящика должны
использовать устойчивого владельца. **Неподписанные запросы
отклоняются даже при `PREKEY_REQUIRE_AUTH=false` или
`QUEUE_REQUIRE_AUTH=false`.** Эти флаги сохраняют свои существующие
значения по умолчанию и унаследованную семантику для аккаунтов без
владельца; явное принятие `false` неподписанных запросов
загрузки/очереди записывает предупреждение об устаревании без
содержимого. Остальные флаги аутентификации без изменений. WebSocket
почтовых ящиков по-прежнему требуют подписи для всех.

Клиент ждёт инициализации подписи перед активностью в очереди,
включая загрузку возвращающегося аккаунта, повышение лидера и
переподключение. Общее ожидание ограничено пятью секундами.
Неподдерживаемые среды выполнения продолжают без подписи немедленно;
застрявшие IDB/разворачивание ключа продолжают без подписи после
предела, затем подписывают, когда готовы. Это сохраняет цикл опроса
живым, **не** является обходом: аккаунты с владельцем не могут
получать от ретранслятора, пока их ключ подписи не станет пригодным.
Развёртывайте обновлённые клиентские ресурсы вместе с Worker, чтобы
избежать старой гонки при запуске.

Миграция не может восстановить владение из бандла, который истёк
**до** того, как его владелец был сохранён. Первая регистрация
остаётся TOFU. Записи владения используют существующий бэкенд KV:
конечная согласованность и конкурентные записи не делаются этой
сменой линеаризуемыми. Доказательства сохраняют существующее
пятиминутное окно свежести и привязку операция/полезная нагрузка;
идентичные повторы внутри окна не являются одноразовым протоколом
nonce.

Записи присутствия и выдача учётных данных TURN уже требуют
*зарегистрированного* аккаунта (присутствующий бандл prekey) по
умолчанию, и каждый клиент регистрируется автоматически. Heartbeat
присутствия дополнительно несёт доказательство владения Ed25519 (beat
подписывает поля, которые хранит), которое Worker проверяет всякий
раз, когда оно представлено — `PRESENCE_SIGN_REQUIRE_AUTH=true`
делает это доказательство обязательным. Остальные флаги подписи
Ed25519 остаются opt-in; `wrangler.toml` документирует каждый из них и
почему (клиенты в средах без WebCrypto Ed25519 вообще не могут
подписывать).

Устаревший простой ретранслятор (`/api/msg/send`, `/api/msg/poll`)
устарел: его ответы несут заголовок `Deprecation: true`, а путь sealed
является маршрутом по умолчанию для каждого текущего клиента. Как
только вы подтвердили, что ни одному живому клиенту больше не нужен
запасной вариант, отключите его полностью:

```bash
wrangler pages secret put PLAIN_PATH_DISABLED   # set to: true
```

### Масштабирование за пределы бесплатного тарифа

Когда вы перерастёте бесплатный тариф (платный план Workers Paid за
$5/месяц):

| Ресурс | Платный план |
|----------|-----------|
| Запросы к Worker | 10 миллионов/месяц |
| Записи KV | 1 миллион/месяц |
| Хранилище KV | 1 ГБ включено |
| Время CPU | 30 секунд/запрос |

Это поддерживает **тысячи одновременных пользователей**.
