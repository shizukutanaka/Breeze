Υπάρχουν δύο τρόποι να λειτουργήσετε μια αναμετάδοση (relay) του Breeze:

1. **Αυτο-φιλοξενούμενη (Node + Docker)** — η αναμετάδοση στο δικό σας μηχάνημα ή
   VPS: ένα container, ένας τόμος δεδομένων, η εγγραφή κλειστή από
   προεπιλογή. Ξεκινήστε εδώ αν η αναμετάδοση είναι για εσάς και τους ανθρώπους σας.
2. **Cloudflare** — η εγκατάσταση επίσημου τύπου στο δωρεάν επίπεδο
   του Cloudflare (η αναμετάδοση που λειτουργεί το ίδιο το Breeze). Ξεκινήστε εκεί αν θέλετε
   μια δημόσια αναμετάδοση χωρίς διακομιστή προς συντήρηση.

Και οι δύο τρέχουν τον ίδιο ακριβώς κώδικα χειρισμού· μια αναμετάδοση είναι ένα απλό,
εναλλάξιμο γραμματοκιβώτιο και στις δύο περιπτώσεις, και κάθε πελάτης (client) συνεργάζεται με
κάθε αναμετάδοση.

## Αυτο-φιλοξενία με Docker

```bash
# 1. Get the code
git clone https://github.com/shizukutanaka/Breeze.git && cd Breeze

# 2. Start it, with your own Breeze ID admitted (see "Registration"
#    below for how to find it — you can also start closed-to-everyone
#    and add IDs later)
BREEZE_ALLOWLIST=<your Breeze ID> docker compose up -d

# 3. Watch the first-boot log — it prints your relay identity
#    fingerprint; write it down (see "Relay identity")
docker compose logs breeze
```

Η αναμετάδοση εξυπηρετεί απλό HTTP στη θύρα 8787 μέσα στο container.
**Τερματίστε το TLS σε έναν αντίστροφο διαμεσολαβητή (reverse proxy) μπροστά της** (Caddy, nginx,
Traefik, ένα Cloudflare Tunnel, …): τα προγράμματα περιήγησης θα χρησιμοποιήσουν μια αναμετάδοση
μόνο μέσω HTTPS/WSS. Όταν το κάνετε, ορίστε `TRUST_PROXY: "true"` στο
`docker-compose.yml` ώστε ο περιορισμός ρυθμού να βασίζεται στην πραγματική διεύθυνση του πελάτη
— και μην το ορίζετε ποτέ χωρίς έναν τέτοιο διαμεσολαβητή, επειδή η κεφαλίδα
στην οποία βασίζεται μπορεί να πλαστογραφηθεί από οποιονδήποτε μπορεί να φτάσει απευθείας την είσοδο.

Εκτελέστε ακριβώς **ένα** container πάνω στον τόμο δεδομένων: ο περιοριστής
ρυθμού βρίσκεται στη μνήμη, ανά διεργασία, και οι λειτουργίες κάθε γραμματοκιβωτίου
σειριοποιούνται μέσα σε εκείνη τη διεργασία, οπότε ένα δεύτερο αντίγραφο δεν θα διατηρούσε
καμία από τις δύο ιδιότητες. Κλιμακώστε δίνοντας στη μία διεργασία ένα μεγαλύτερο μηχάνημα.

### Εγγραφή: κλειστή από προεπιλογή

Μια αυτο-φιλοξενούμενη αναμετάδοση στην οποία θα μπορούσε να εγγραφεί οποιοσδήποτε στο διαδίκτυο
θα αναδημιουργούσε την οικονομία spam/κατάχρησης που τα όρια της επίσημης αναμετάδοσης
υπάρχουν για να ελέγχουν, οπότε **η συσκευασία Docker παραδίδεται κλειστή**: το αρχείο
compose περνά ένα `REGISTRATION_ALLOWLIST` (ενδεχομένως κενό) και
μόνο τα Breeze ID που βρίσκονται σε αυτό μπορούν να *δημιουργήσουν λογαριασμούς* (μια πρώτη μεταφόρτωση
prekey). Το κλείσιμο της εγγραφής δεν επηρεάζει ποτέ τα άτομα που ήδη στεγάζονται στην
αναμετάδοση — οι μεταφορτώσεις, οι καταθέσεις, τα rendezvous και τα poll τους δεν
φραγονται — και το άνοιγμα της εγγραφής είναι μια ρητή επιλογή, ποτέ η
προεπιλογή.

- **Το Breeze ID σας** είναι το αναγνωριστικό 12 χαρακτήρων στον σύνδεσμο
  πρόσκλησής σας (οι πρώτοι 12 χαρακτήρες της τιμής `pub` του). Ζητήστε από κάθε άτομο
  που προσκαλείτε το δικό του με τον ίδιο τρόπο — το ID είναι ένα δημόσιο αναγνωριστικό
  που οι επαφές ήδη ανταλλάσσουν, όχι μυστικό.
- **Εισδοχή ατόμων** καταχωρώντας τα ID τους: ορίστε
  `BREEZE_ALLOWLIST=id1,id2,…` στο shell σας ή σε ένα αρχείο `.env` δίπλα στο
  `docker-compose.yml`, και μετά πάλι `docker compose up -d`.
- **Ξεκινήστε τώρα, εισδεχθείτε αργότερα**: χωρίς ορισμένο `BREEZE_ALLOWLIST`, η
  αναμετάδοση τρέχει κλειστή για όλους — το αρχείο καταγραφής εκκίνησης το λέει — και κανείς
  δεν μπορεί να εγγραφεί μέχρι να προσθέσετε ID.
- **Ανοικτή αναμετάδοση** (οποιοσδήποτε μπορεί να εγγραφεί): αποσχολιάστε το
  `REGISTRATION_OPEN: "1"` στο `docker-compose.yml`. Αν το κάνετε, η οικονομία της κατάχρησης είναι δική σας.

### Ποσόστωση χρήσης: απενεργοποιήστε την στη δική σας αναμετάδοση

Το worker παραδίδεται με μια **ποσόστωση δίκαιης χρήσης (fair-use)** ενεργοποιημένη: ανά
γραμματοκιβώτιο, το πολύ 10.000 καταθέσεις/ημέρα και 200.000/μήνα (μια κατάθεση είναι
ένας πλήρης κύκλος παράδοσης — δείτε το `docs/COST_MODEL.md` §10 για την
πολιτική και τους αριθμούς). Αυτό το πλαίσιο υπάρχει για την *κοινόχρηστη προεπιλεγμένη
αναμετάδοση*, η οποία λειτουργεί ως μια δωρεάν είσοδος της οποίας τα μεταβλητά κόστη ο
χειριστής θα έπρεπε αλλιώς να φέρει για όλους. **Σε μια αναμετάδοση που λειτουργείτε
για εσάς και τους ανθρώπους σας, το πλαίσιο δεν έχει νόημα — απενεργοποιήστε
το**:

```bash
USAGE_QUOTA_ENABLED=false
```

Ορίστε το όπου η αναμετάδοσή σας διαβάζει το περιβάλλον της (το shell ή
το `.env` δίπλα στο `docker-compose.yml`, το περιβάλλον της διεργασίας Node,
ή τα μυστικά (secrets) του Cloudflare Pages). Υπάρχουν δύο γειτονικές ρυθμίσεις αν
λειτουργείτε μια κοινοτική αναμετάδοση και *θέλετε* ένα πλαίσιο:
το `USAGE_QUOTA_DAILY` και το `USAGE_QUOTA_MONTHLY` επαναρυθμίζουν τα ανώτατα όρια.
Σημειώσεις που έχουν σημασία:

- Η ποσόστωση επιβάλλεται μόνο όταν τα γραμματοκιβώτια ζουν σε Durable
  Objects (`MAILBOX_BACKEND=do`, η προεπιλογή σε αυτόν τον host)· στο backend
  KV είναι ένα τεκμηριωμένο no-op.
- Πάνω από το ανώτατο όριο, οι αποστολείς λαμβάνουν ένα ρητό `429 USAGE_QUOTA_EXCEEDED`
  (με το παράθυρο και το όριό του) αντί για μια σιωπηλή απόρριψη — το μήνυμα
  παραμένει στο outbox του αποστολέα, και ο παραλήπτης παραμένει
  προσβάσιμος μέσω P2P και μέσω οποιασδήποτε άλλης οικιακής αναμετάδοσης.

### Ταυτότητα της αναμετάδοσης

Κατά την πρώτη εκκίνηση, η αναμετάδοση δημιουργεί ένα μόνιμο κλειδί ταυτότητας Ed25519
*μέσα στον τόμο δεδομένων* και εκτυπώνει το αποτύπωμά του (fingerprint) στο αρχείο καταγραφής:

```
relay identity: NEW key generated — fingerprint 3F2A 9C41 …
```

Το αποτύπωμα ταυτοποιεί τη *δική σας* αναμετάδοση: δώστε το στους χρήστες σας
εκτός ζώνης (out-of-band: αυτοπροσώπως, μέσω άλλου καναλιού) ώστε να μπορούν να αναγνωρίσουν
την αναμετάδοση που τους δόθηκε ως αυτή που λειτουργείτε εσείς. Το ίδιο αποτύπωμα
εκτυπώνεται σε κάθε εκκίνηση· αν αλλάξει ποτέ, ο τόμος δεδομένων
αντικαταστάθηκε — διερευνήστε πριν πείτε στους χρήστες να εμπιστευτούν το νέο.

Οι πελάτες επαληθεύουν και καρφιτσώνουν (pin) αυτόματα αυτό το κλειδί (στάδιο 2, βήμα 4): κατά την
πρώτη επαφή ένας πελάτης προκαλεί την αναμετάδοση να υπογράψει με το κλειδί
(`/api/relay/attest`), αποθηκεύει το επαληθευμένο κλειδί μαζί με τον λογαριασμό, και
το επαληθεύει ξανά σε κάθε μεταγενέστερη συνεδρία. Το αποτύπωμα που δείχνει ο πελάτης
(στο `/security`, και στο toast κατά το πρώτο καρφίτσωμα) προέρχεται από
το ίδιο κλειδί — συγκρίνετέ το με τη γραμμή του αρχείου καταγραφής εκκίνησης παραπάνω. Αν το κλειδί
αλλάξει ποτέ, οι πελάτες **σταματούν να μιλούν στην αναμετάδοση** και προειδοποιούν τον
χρήστη· ποτέ δεν ξανακαρφιτσώνουν σιωπηλά. Αντιμετωπίστε μια αλλαγή αποτυπώματος ως ένα
γεγονός ρήξης: δεν υπάρχει κουμπί εντός εφαρμογής «εμπιστεύομαι το νέο κλειδί» στο
βήμα 4, οπότε μετά από μια πραγματική απώλεια τόμου οι χρήστες σας πρέπει να διαγράψουν τα
αποθηκευμένα δεδομένα της εφαρμογής για τον λογαριασμό τους και να ξανακαρφιτσώσουν στην πρώτη επαφή —
ανακοινώστε πρώτα το νέο αποτύπωμα εκτός ζώνης, αλλιώς δεν μπορούν να ξεχωρίσουν
το νέο σας κλειδί από αυτό ενός επιτιθέμενου.

### Αντίγραφο ασφαλείας και επαναφορά

**Ο τόμος δεδομένων είναι ολόκληρη η κατάσταση της αναμετάδοσης**: ένα μόνο αρχείο SQLite
που περιέχει τον κατάλογο, τα γραμματοκιβώτια και το κλειδί ταυτότητας της αναμετάδοσης.
Δεν υπάρχει τίποτε άλλο για αντίγραφο ασφαλείας.

```bash
# Back up: copy the database out of the (stopped) container
docker compose stop
docker cp "$(docker compose ps -aq breeze)":/data/breeze-relay.db ./breeze-relay-backup.db
docker compose start

# Restore: copy the backup back in as /data/breeze-relay.db before
# starting, and the relay serves identically — same fingerprint.
docker compose stop
docker cp ./breeze-relay-backup.db "$(docker compose ps -aq breeze)":/data/breeze-relay.db
docker compose start
```

### Ενημέρωση

```bash
git pull origin main
docker compose up -d --build
```

Η κατάσταση ζει στον τόμο, όχι στην εικόνα (image), οπότε η ενημέρωση δεν αγγίζει ποτέ
τα δεδομένα των χρηστών σας.

## Αυτο-φιλοξενία με σκέτο Node (χωρίς Docker)

```bash
node server/index.js   # Node ≥ 24, no npm dependencies to install
```

Η διαμόρφωση γίνεται μόνο με μεταβλητές περιβάλλοντος — το `server/README.md`
τις απαριθμεί όλες. Δύο διαφορές από τη διαδρομή Docker:

- Το **αρχείο δεδομένων** έχει προεπιλογή `./breeze-relay.db` (παράκαμψη με
  `BREEZE_DB_PATH`)· είναι η ίδια κατάσταση ενός αρχείου, με την ταυτότητα της αναμετάδοσης
  να περιλαμβάνεται. Κάντε του αντίγραφο ασφαλείας με τον ίδιο τρόπο: σταμάτημα, αντιγραφή, επανεκκίνηση.
- **Η εγγραφή είναι ανοικτή εκτός αν την κλείσετε**: η κλειστή προεπιλογή
  είναι ιδιότητα της συσκευασίας Docker. Για να κλείσετε μια σκέτη είσοδο, ορίστε
  `REGISTRATION_ALLOWLIST=id1,id2` (ή μια κενή τιμή για
  κλειστή-για-όλους)· το `REGISTRATION_OPEN=1` την ανοίγει ξανά ρητά.

## Εγκατάσταση Cloudflare

### Ελάχιστη εγκατάσταση (0 δολάρια/μήνα, 5 λεπτά)

```bash
# 1. Install Wrangler CLI
npm install -g wrangler

# 2. Login to Cloudflare
wrangler login

# 3. Deploy
wrangler pages deploy . --project-name=breeze

# 4. Create a KV namespace and declare it in wrangler.toml
wrangler kv:namespace create KV
# Copy the new namespace's ID and put it in wrangler.toml, replacing the
# id in the [[kv_namespaces]] section (binding = "KV"). Pages takes its
# bindings from wrangler.toml; a binding set only in the Dashboard is
# NOT applied while a wrangler.toml exists.
# Then deploy again so the binding takes effect:
wrangler pages deploy . --project-name=breeze

# 5. Visit https://breeze.pages.dev
```

**Αυτό είναι όλο.** Όλες οι λειτουργίες δουλεύουν εκτός από τις ειδοποιήσεις push. Σημειώστε
ότι η εγγραφή σε μια εγκατάσταση Cloudflare είναι **ανοικτή** εκτός αν ορίσετε
εσείς οι ίδιοι το `REGISTRATION_ALLOWLIST` (δείτε το `.env.example`)· η
συσκευασία κλειστή-από-προεπιλογή είναι η διαδρομή Docker παραπάνω.

### Τι λειτουργεί στα 0 δολάρια

| Λειτουργία | Κατάσταση | Σημειώσεις |
|---------|--------|-------|
| Κρυπτογραφημένη συνομιλία E2E | ✓ | Πλήρες Double Ratchet |
| Μηνύματα P2P | ✓ | WebRTC DataChannel |
| Φωνητικές/βιντεοκλήσεις | ✓ | WebRTC + δωρεάν STUN |
| Αναμετάδοση TURN | ✓ | Open Relay (20 GB/μήνα δωρεάν) |
| Ομάδες (100 μέλη) | ✓ | Sender Key O(1) |
| Μεταφορά αρχείων | ✓ | Έως 50 MB μέσω P2P |
| 8 γλώσσες | ✓ | EN + 7 πλήρη locale, αυτόματη ανίχνευση |
| Εκτός σύνδεσης/PWA | ✓ | Service Worker |

Η πολυεπίπεδη χρέωση λογαριασμών (Lite/Plus/Pro) δεν είναι διαθέσιμη — δείτε
την ενότητα «Removed: multi-account billing» του [SECURITY.md](../../SECURITY.md). Κάθε λογαριασμός παίρνει
απεριόριστους τοπικούς υπολογαριασμούς δωρεάν, χωρίς καμία φραγή σχεδίου (plan gating).

### Όρια του δωρεάν επιπέδου

| Πόρος | Δωρεάν επίπεδο | Χρήση ανά ενεργό χρήστη |
|----------|-----------|----------------------|
| Αιτήματα Worker | 100.000/ημέρα | ~500/ημέρα (polling + σηματοδότηση) |
| Αναγνώσεις KV | 100.000/ημέρα | ~200/ημέρα |
| Εγγραφές KV | 1.000/ημέρα | ~350/ημέρα (βελτιστοποιημένο) |
| Αποθήκευση KV | 1 GB | ~10 KB/χρήστη |
| Στατικά αρχεία | Απεριόριστα | ~400 KB (ένα μόνο HTML) |

**Υποστηρίζει ~3 ταυτόχρονους ενεργούς χρήστες στο δωρεάν επίπεδο.**

### Προσθήκη προαιρετικών λειτουργιών

#### Ειδοποιήσεις push (δωρεάν)

```bash
# Generate VAPID keys
npx web-push generate-vapid-keys

# Set secrets
wrangler pages secret put VAPID_PUBLIC_KEY
wrangler pages secret put VAPID_PRIVATE_KEY
```

#### Διακομιστής TURN (για περιοριστικά δίκτυα)

Το TURN είναι ο τρόπος με τον οποίο οι κλήσεις και οι συνδέσεις μόνο-μέσω-αναμετάδοσης (που κρύβουν την IP) διασχίζουν
τα περιοριστικά NAT. Ποιο TURN παραδίδει η αναμετάδοσή σας είναι δική **σας** επιλογή ως
χειριστή — το Worker δοκιμάζει, κατά σειρά:

```bash
# Option A: Cloudflare Calls ($0.05/GB, global anycast)
wrangler pages secret put TURN_KEY_ID
wrangler pages secret put TURN_KEY_API_TOKEN

# Option B: your own coturn (HMAC time-limited credentials — the Worker
# mints a 24h username/credential per registered user from the secret)
#   coturn: use-auth-secret, static-auth-secret=<same secret>
wrangler pages secret put TURN_URL      # turn:your-server:3478
wrangler pages secret put TURN_SECRET

# Option C: static credentials (metered.ca, Twilio, …)
wrangler pages secret put TURN_URL
wrangler pages secret put TURN_USERNAME
wrangler pages secret put TURN_CREDENTIAL

# Option D: No config → free Open Relay (20GB/month). This is a third
# party's PUBLIC quota, shared with every unconfigured relay — fine for
# a first run, not a foundation. Opt out explicitly and callers get
# STUN only (some restrictive-NAT calls will then fail, visibly):
wrangler pages secret put TURN_OPENRELAY_FALLBACK   # set to: false
```

**Επαληθεύστε τι πραγματικά διαμορφώσατε:** το `GET /api/health` αναφέρει τον
πραγματικό τρόπο ως `turnProvider` (`cloudflare` | `custom` | `static` |
`openrelay` | `none`). Το παλαιότερο boolean `turn` αντικατοπτρίζει μόνο το
`TURN_URL`, οπότε δείχνει `false` για τη συνιστώμενη Επιλογή A — χρησιμοποιήστε το
`turnProvider`. Οι πελάτες δείχνουν τον ίδιο πάροχο στο `/security`, οπότε ένας
χρήστης που βρίσκεται στην εφεδρεία Open Relay μπορεί να δει ότι ένας τρίτος αναμεταδίδει τα
μέσα της κλήσης του (μόνο μεταδεδομένα — τα ίδια τα μέσα είναι κρυπτογραφημένα με DTLS-SRTP).

#### Σκλήρυνση ταυτοποίησης και η διαδρομή απλής αναμετάδοσης

Οι μεταφορτώσεις prekey διατηρούν πλέον την ιδιοκτησία υπογραφής ξεχωριστά στο
`prekey-owner:<userId>` **χωρίς TTL**. Η υπάρχουσα ιδιοκτησία δέσμης (bundle) μεταναστεύει νωχελικά
στην επόμενη μεταφόρτωση, πριν γίνει αποδεκτή μια αντικατάσταση. Οι νέες δέσμες Ed25519 επίσης
δημιουργούν εκείνη την εγγραφή. Διατηρήστε αυτές τις εγγραφές όταν εκκαθαρίζετε ληγμένες δέσμες prekey:
η αναμονή για τη λήξη της δέσμης δεν πρέπει να επιτρέπει έναν νέο ιδιοκτήτη. Η εναλλαγή (rotation) απαιτεί μια
μεταφόρτωση υπογεγραμμένη από τον προηγούμενο ιδιοκτήτη, δεσμεύοντας το νέο κλειδί στο υπάρχον digest
της μεταφόρτωσης. Η ταυτοποιημένη `/account/delete` διαγράφει και τις δύο εγγραφές και μπορεί να ταυτοποιηθεί
έναντι του ιδιοκτήτη ακόμη και μετά τη λήξη της δέσμης. Δεν υπάρχει επαναφορά κλειδιού ιδιοκτήτη που χάθηκε.

Για λογαριασμούς με αυτή την εγγραφή, η μεταφόρτωση και το poll μηνυμάτων/sealed, το sealed ACK και οι
αποδείξεις WebSocket του γραμματοκιβωτίου πρέπει να χρησιμοποιούν τον ανθεκτικό ιδιοκτήτη. **Τα ανυπόγραφα αιτήματα
απορρίπτονται ακόμη και με `PREKEY_REQUIRE_AUTH=false` ή `QUEUE_REQUIRE_AUTH=false`.**
Αυτές οι σημαίες διατηρούν τις υπάρχουσες προεπιλογές τους και την παλαιά σημασιολογία τους για λογαριασμούς
χωρίς ιδιοκτήτη· η ρητή αποδοχή `false` ανυπόγραφων αιτημάτων μεταφόρτωσης/ουράς
καταγράφει μια προειδοποίηση κατάργησης (deprecation) χωρίς περιεχόμενο. Οι υπόλοιπες σημαίες ταυτοποίησης είναι αμετάβλητες.
Τα WebSocket του γραμματοκιβωτίου εξακολουθούν να απαιτούν υπογραφές από όλους.

Ο πελάτης περιμένει την αρχικοποίηση της υπογραφής πριν από τη δραστηριότητα ουράς, συμπεριλαμβανομένης
της εκκίνησης λογαριασμού που επιστρέφει, της προαγωγής σε αρχηγό (leader promotion) και της επανασύνδεσης. Η κοινή αναμονή είναι
περιορισμένη στα πέντε δευτερόλεπτα. Τα μη υποστηριζόμενα runtime συνεχίζουν ανυπόγραφα αμέσως·
η κολλημένη αποτύλιξη IDB/κλειδιού συνεχίζει ανυπόγραφη μετά το όριο, και μετά υπογράφει όταν είναι έτοιμη.
Αυτό κρατά τον βρόχο poll ζωντανό, **δεν** είναι παράκαμψη: οι λογαριασμοί με ιδιοκτήτη δεν μπορούν να
λάβουν από την αναμετάδοση μέχρι το κλειδί υπογραφής τους να είναι χρησιμοποιήσιμο. Εγκαταστήστε τα ενημερωμένα αρχεία
πελάτη μαζί με το Worker για να αποφύγετε την παλιά κούρσα εκκίνησης.

Η μετανάστευση δεν μπορεί να ανακτήσει την ιδιοκτησία από μια δέσμη που έληξε **πριν** ο
ιδιοκτήτης της διατηρηθεί. Η πρώτη εγγραφή παραμένει TOFU. Οι εγγραφές ιδιοκτησίας χρησιμοποιούν το
υπάρχον backend KV: η ενδεχόμενη συνέπεια (eventual consistency) και οι ταυτόχρονες εγγραφές δεν γίνονται
γραμμικοποιήσιμες (linearizable) από αυτή την αλλαγή. Οι αποδείξεις διατηρούν το υπάρχον παράθυρο φρεσκάδας πέντε λεπτών
και τη δέσμευση λειτουργίας/φορτίου· οι ίδιες επαναλήψεις εντός παραθύρου δεν είναι ένα
πρωτόκολλο nonce μίας χρήσης.

Οι εγγραφές παρουσίας (presence) και η έκδοση διαπιστευτηρίων TURN απαιτούν ήδη έναν *εγγεγραμμένο*
λογαριασμό (παρούσα δέσμη prekey) από προεπιλογή, και κάθε πελάτης εγγράφεται
αυτόματα. Οι παλμοί παρουσίας (heartbeat) φέρουν επιπλέον μια απόδειξη ιδιοκτησίας Ed25519
(ο παλμός υπογράφει τα πεδία που αποθηκεύει), την οποία το Worker επαληθεύει
όποτε παρουσιάζεται μία — το `PRESENCE_SIGN_REQUIRE_AUTH=true` κάνει εκείνη την
απόδειξη υποχρεωτική. Οι υπόλοιπες σημαίες υπογραφής Ed25519 παραμένουν opt-in·
το `wrangler.toml` τεκμηριώνει την καθεμία και το γιατί (οι πελάτες σε runtime χωρίς
WebCrypto Ed25519 δεν μπορούν να υπογράψουν καθόλου).

Η παλαιά απλή αναμετάδοση (`/api/msg/send`, `/api/msg/poll`) έχει καταργηθεί (deprecated): οι απαντήσεις της
φέρουν μια κεφαλίδα `Deprecation: true`, και η διαδρομή sealed είναι η
προεπιλεγμένη διαδρομή για κάθε τρέχοντα πελάτη. Μόλις επιβεβαιώσετε ότι κανένας ζωντανός
πελάτης δεν χρειάζεται ακόμη την εφεδρεία, απενεργοποιήστε την εντελώς:

```bash
wrangler pages secret put PLAIN_PATH_DISABLED   # set to: true
```

### Κλιμάκωση πέρα από το δωρεάν επίπεδο

Όταν ξεπεράσετε το δωρεάν επίπεδο (σχέδιο Workers Paid 5 δολαρίων/μήνα):

| Πόρος | Πληρωμένο σχέδιο |
|----------|-----------|
| Αιτήματα Worker | 10 εκατομμύρια/μήνα |
| Εγγραφές KV | 1 εκατομμύριο/μήνα |
| Αποθήκευση KV | 1 GB περιλαμβάνεται |
| Χρόνος CPU | 30 δευτερόλεπτα/αίτημα |

Αυτό υποστηρίζει **χιλιάδες ταυτόχρονους χρήστες**.
