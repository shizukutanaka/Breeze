## 1. 長所(実証済みのもののみ)

- **広告ゼロ・トラッキングゼロ・登録ゼロ。** 鍵そのものがIDであり、メールも電話番号も
  Passkeyも要らない。「アカウント作成が面倒」という不満に対する解が *作成という工程の削除* に
  なっている。
- **送信者がリレーから暗号学的に隠れる(Sealed Sender v2)。** 送信者ID・公開鍵・表示名・
  署名鍵・返信プレビュー・マルチデバイス標識を受信者の鍵へ封印(ephemeral X25519 → HKDF
  `breeze-seal-v2` → AES-256-GCM、AADが宛先と時刻を束縛)。初回接触のX3DHヘッダが送信者の
  identity鍵を生バイトで露出していた欠陥も封印済み — **盗聴E2E(`seal.spec.js`)が実バイトを
  検査**して証明している。
- **マルチデバイスが実際に動く。** 受信の両デバイス配送、帰属(副デバイス送信が相手の同じ
  会話に入る)、自己同期(新品のPCが会話ごと復元)、編集・削除の伝播、添付のfan-out —
  すべて `multidevice.spec.js` の5幕で実ブラウザ実証。
- **暗号状態がリロードを生き延びる。** 1:1のDouble Ratchetもグループのsender keyも、
  リロード後に復号・送信が継続する(`lifecycle.spec.js`、本セッションで新規実証)。
- **主張とコードの一致を機械が守る。** ミラードリフト検査(インライン実装 vs 参照実装)、
  CSPハッシュピン留め、死にi18nキー検出、到達不能関数検出 — いずれも**歯があることを
  実証済み**(意図的に壊して BLOCKED を確認してから戻す運用)。
- **「静かなメッセンジャー」の設計。** 返信不要マーク(未読を増やさない)、遅延既読、
  集中モード、端末内だけの重要度判定。LINEが構造的に真似できない差別化(向こうの収益源は
  エンゲージメント)。

## 2. 短所(正直に、原因の所在で分類)

### 2-1. 外部要因で待つもの(こちらで閉じられない)
- **CIが未稼働。** 796+32+39のゲートが自動実行されていない。自動化アカウントに GitHub の
  `workflows` OAuthスコープが無く `.github/workflows/*` をpushできないため。
  手順とワークフロー内容は `docs/CI-SETUP.md` に保全済み。**メンテナが有効化すれば即動く。**
- **ポスト量子(PQXDH)未展開。** ML-KEM のブラウザ実装待ち(~2027)。`src/crypto/pq.js` は
  テスト済みだが未配線。今日の鍵合意は古典的(X25519)。

### 2-2. 意図的な設計上の制限(理由つきで選んだもの)
- **グループ送信はプライマリ端末限定。** 副デバイスを名簿に載せると、メンバー数×端末数の
  肥大とエポックchurnを招く。**黙って捨てず明示的に拒否**し、入力テキストを返す実装。
- **履歴同期なし。** 新しくリンクした端末は空から始まる(Signalと同じ判断)。`/backup` が移行経路。
- **root端末を失うとデバイス管理が不能。** 登記簿の署名者がrootのみ。既存端末のメッセージングは
  継続する。

### 2-3. 残る弱点(内部要因 — 改善余地あり)
- **sealed キューは best-effort(ただし回復あり)。** Cloudflare KV は last-write-wins で
  トランザクションが無く、同一宛先への同時書き込みで封筒を失いうる — しかも両送信者に200が返る
  ため**損失が不可視**だった。送信側で**書き戻し確認と再追加**を実装(送信は3秒ポーリングに比べ
  低頻度なので読み取り1回の増加で済む)。教科書的な「封筒ごとにキーを分ける」は競合を根絶するが、
  最ホットパスの `get` 1回を `list`+メッセージ数分の `get` に置き換えるため、無料枠(書き込み
  1000/日)で presence 書き込みまで絞っている本製品では割に合わないと**計測して**却下した。
  **exactly-once ではなく「回復つき best-effort」**。
- **招待トークンがロスターへの鍵になっている。** `/group/info` は参加せずともメンバーのID・
  公開鍵・表示名を返す。**当初これを「署名でメンバー限定にすれば内部で閉じられる」と評価したが、
  実装して誤りと判明した**: `/group/join` はトークンだけで参加でき(署名も承認も不要)、参加応答が
  ロスターをそのまま返す。つまり読み取りを塞いでも、攻撃者は join して同じものを、しかも
  メッセージ受信権つきで得る。**弱い読み取りを塞いで強い書き込みを開けておく制御は、
  セキュリティに見えて実効性がない**ので撤回した(既存13テストの失敗が再考の signal になった)。
  実効的な対策は *join* 側を絞ること(管理者承認など)であり、それはプライバシー修正ではなく
  プロダクト仕様の決定。現時点の正しい理解は **「招待リンク = グループ参加権とほぼ等価」** であり、
  リンクの取り扱いをそう説明することが唯一の緩和策。
- **失効の伝播が最大5分遅延。** 送信側キャッシュTTLに等しい。
- **バックグラウンドのポーリングが15秒間隔。** 前面なら3秒。PWAを裏に回すと着信が最大15秒遅れる。
- **クラウドバックアップは90日で消える。** 最終アップロードから。期限を返して表示するようにしたが、
  自動延命はしていない。

### 2-3b. 到達不能だった機能(発見と修正)
**マルチアカウントは完成していたのに、UIから一度も到達できなかった。** 切替・per-account DB・
未読バッジ・Ctrl+1〜9・改名/削除まで実装済みなのに、2個目を作る「+」が**アカウントタブバーの
内側**にあり、そのタブバーは「アカウント2個以上」で初めて描画される — ブートストラップ・
デッドロック(3セッション実測: `#acc-tabs` 0個・`.acc-add` 0個)。さらに作成できても、新
アカウントはIDが無くセットアップ画面に出るが、タブバーは `#msg-main` の内側にあり隠れるため
**新アカウントに閉じ込められる**(脱出は未公開のCtrl+1〜9のみ)。設定パネルに入口を追加し、
セットアップ画面でも切替可能にした。削除ではなく修正を選んだ根拠は、機能が首尾一貫して
完成しており欠陥が「条件1つ」だったこと。

**同じクラスがもう2件見つかった(死んだ配線)。** `_DOM.get('id')` は存在しないIDに `null` を
返し、コードは `?.` を多用するため、**要素の削除・改名はリスナーを静かに無力化する**。
全77件を照合したところ3件が不在IDを指していた:
- `b-msg-backup` → **ローカル暗号化バックアップの作成が到達不能**。復元側はサイドバーへの
  ドラッグ&ドロップで生きていたため、**作れないファイルを復元できる**という非対称な行き止まり。
  SECURITY.md が root鍵喪失の回復経路として案内しているのはこれであり、クラウド版が90日で
  消えるのに対しローカルファイルは無期限 — 失われていた側が価値の高い方だった。
  `/backup` パネルに「ファイルに保存/ファイルから復元」を追加して解決。
- `b-msg-panic` / `contact-sort` → 機能自体は `/panic`(+Ctrl+Shift+Backspace)と `/sort` で
  到達可能なため、残骸のリスナーのみ削除。
再発防止として `tools/dead-wiring.mjs` を新設し validate.sh に組み込み(40チェックに拡張)。

### 2-4. プロセスの弱点(本セッション最大の学び)
**E2Eが「初回セッション」に偏っていた。** 10本のspecのうちリロードを行うのは3本のみで、
その3本はすべて本セッションで追加したもの。結果、**復帰ユーザー全員でアプリが機能停止する
バグ(TDZによる起動中断 → 連絡先0件・メッセージ受信ゼロ)が29本の緑をすり抜けた**。
テストが緑であることは「テストした範囲が正しい」以上を意味しない。
→ 是正済み(リロード系3本を追加)。今後は**同種の偏りが他にないか**を点検軸とする。

## 4. この評価の使い方
新しい主張を足すときは、**まずそれを反証するテストを書く**。本セッションで見つかった重大な
欠陥(偽の監査ログ、届かない924言語テーブル、リレーに見えていた送信者、黙って消える
グループ送信、起動中断)は、すべて「主張はあるが検証が無い」箇所から出た。

そして**改善案そのものも検証対象**である。上記2-3の `/group/info` は「内部で閉じられる」と
書いた直後に実装し、**同じトークンで join できる以上まったく効かない**ことが分かって撤回した。
既存テストが13本落ちたことが「範囲が想定より広い=前提を疑え」という合図だった。
**塞ぐ前に、攻撃者がその制御を迂回する最短経路を数えること。**
